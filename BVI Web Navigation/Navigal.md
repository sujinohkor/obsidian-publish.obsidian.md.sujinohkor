- **스크린리더 사용자가 필요한 기능을 말하면, AI가 웹페이지에서 해당 기능을 찾아 조작하기 쉬운 맞춤 인터페이스로 모아주는 시스템을 제안**
- 예를 들어 “가격/사이즈/색상 필터를 보여줘”라고 하면, 페이지 곳곳을 탐색할 필요 없이 한 패널에서 조작하게 해줌. **AI는 기능을 찾아주고, 사용자는 직접 조작하고 원본도 확인할 수 있다는 점**이 핵심

# RQ / Research Goal
웹사이트마다 기능의 위치/구조가 달라서, 스크린리더 사용자는 필요한 기능을 찾기 위해 페이지 구조를 익히고 여러 요소를 거쳐야 함. 연구 목표는 **사용자가 페이지 구조를 일일이 탐색하지 않고도, 자신의 목적에 맞는 기능에 직접 접근하고 조작하게 하는 것**으로, 이 때에 사용자의 통제권과 원본 확인 가능성을 유지하려고 함.

사용자 연구에서는 아래 사항들을 확인하고자 함.
- Navigal이 기존 스크린리더 단독 사용보다 **주관적 작업 부담과 탐색 경험을 개선하는가?**
- 사용자는 **개인화된 생성형 탐색 인터페이스라는 개념을 어떻게 받아들이는가?**

# Approach
핵심은 **tether(원래 웹페이지 요소에 연결된, 접근 가능한 대리 컨트롤)**로, 사용자가 "가격/사이즈/색상 필터를 보여줘"라고 입력하면 아래와 같이 작동함.
1) **의도 입력:** 사용자가 필요한 기능이나 정보를 자연어로 설명
2) **요소 탐색:** LLM이 DOM 분석도구 등을 이용해 관련 페이지 요소를 검색
3) **인터페이스 생성:** 해당 요소를 버튼/체크박스/입력창 등으로 만들어 별도 패널에 제공
4) **실제 페이지 조작:** 사용자가 생성된 컨트롤을 조작하면 원래 페이지에 반영
5) **확인 및 재사용:** 원본 요소로 이동해 확인하고, 저장된 연결을 페이지 변화에 맞춰 재연결

크롬 확장 프로그램으로 구현했고, 페이지가 바뀌어도 같은 목적의 기능을 다시 찾아 연결하는 방식을 설계함.

검증 항목은 아래와 같음.
- **기술평가:** 19개 웹사이트의 20개 과제에서 연결 정확성, 탐색 단계 수, 지연시간과 비용 측정
- **탐색적 사용자 연구:** 시각장애인 7명이 아마존 쇼핑 과제를 <스크린리더 단독>과 <Navigal 병행 조건>으로 수행. NASA-TLX, 탐색경험 설문, 인터뷰로 비교

# Findings
1) **과제 지원:** 20개 중 **15개 완전 수행, 3개 부분 수행, 2개 실패**
2) **생성 정확성:** 66개 tether 중 **59개 정확함(89.4%),** 6개 부분정확, 1개 부정확
3) 탐색 단계: 공통으로 도달 가능한 요소 기준 중앙값이 **순차탐색 39단계 → Navigal 6단계**
4) **처리 부담:** 시스템 처리지연 중앙값은 과제당 약 34초, 비용은 약 $0.10
5) **사용자 부담:** 정신적 부담/시간 압박/좌절감/노력 감소, 지각된 수행도 개선이 통계적으로 유의함
6) **탐색 경험:** 지각된 효율성과 필요한 기능의 위치를 안다는 확신이 유의하게 개선됨
7) **수용성:** 7명 전원이 연구 이후에도 사용하고 싶다고 응답

정성적 발견은 아래와 같음.
- **웹사이트 구조에 대한 의존이 감소함:** 사용자는 필터가 어디에 있는지 알아내는 대신, 필요한 기능을 요청해서 바로 접근했음
- **원본 확인 기능이 신뢰에 중요함:** 일부 참여자는 AI의 자율 실행보다 직접 조작하는 방식을 선호했고, 특히 구매 상황에서 원래 페이지로 돌아가 확인할 수 있다는 점을 높게 평가함

단, **모든 지표가 통계적으로 유의하지는 않음.** 통제감, 반복 접근, 적응성 등은 긍정적인 경향을 보였지만, 유의한 개선으로 보고되지는 않음.

# Limitations
**저자가 명시한 한계**
- **장기 사용 미검증:** 사용자가 오랫동안 tether를 관리하고 재사용하는 양상은 확인하지 못함
- **사이트 간 적응 미검증:** 핵심 기능인 다른 사이트로의 연결 이전을 기술 평가에서 직접 검증하지 않았으며, 사용자 연구에서도 지속 연결과 적응 기능은 주로 후속 시연으로 소개
- **사용법에 대한 오해:** 일부 참여자는 현재 열린 페이지를 대상으로 하는 도구를 일반 웹 검색엔진처럼 이해함
- **커스텀 위젯 조작 실패:** 요소를 제대로 찾아도 사이트 자체 구현 때문에 조작이 반영되지 않는 경우가 있었음
- **관련 요소 누락 및 모델 의존:** 일부 결과를 놓쳤고, 정확도/속도/비용이 기반 LLM의 성능에 의존

**연구 설계를 보고 추가로 짚을 한계**
- **7명, 아마존 쇼핑 중심의 탐색적 연구**라 다양한 사용자와 과제로 일반화하기 어려움
- 실험자가 도움을 제공했으므로 **독립적인 실제 사용 성능을 입증한 연구로 보기는 어려움**
- 탐색 단계 계산은 **질의 입력을 제외**했으므로, 단계 감소를 전체 작업시간 감소로 해석하면 안 됨
- 구조적 단축키를 최적으로 사용하는 이론적 최단 경로는 중앙값 **4단계.** 즉, Navigal의 6단계는 **순차 탐색 대비 개선**이며, 모든 기존 탐색 방식보다 빠르다는 뜻은 아님
