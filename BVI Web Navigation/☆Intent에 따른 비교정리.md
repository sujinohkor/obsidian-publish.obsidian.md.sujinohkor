| 구분                   | 연구에서 사용할 의미                                      | 예시                             |
| -------------------- | ------------------------------------------------ | ------------------------------ |
| **intent 100%**      | 찾을 정보나 수행할 작업이 구체적으로 정해진 상태                      | “이 상품의 반품 기간을 알고 싶다”           |
| **0 < intent < 100** | 관심 주제나 상위 목표는 있지만, **구체적 질문·조건·선택 기준이 덜 정해진** 상태 | “노트북을 사고 싶은데 무엇을 비교해야 할지 모르겠다” |
| **intent 0%**        | **아직 특정 탐색 대상 없이,** 페이지를 접하며 관심 대상을 발견하는 상태      | “어떤 내용이 있는지 일단 둘러보고 싶다”        |

# intent 100%: 명시된 목표에 접근하는 연구
## [[Navigal]] - 가장 대표적인 사례
- **본문 근거:** 사용자가 원하는 컨트롤을 자연어로 설명하면, 해당 요소에 직접 연결되는 개인화 인터페이스를 생성하는 방식. 사용자가 도달하려는 대상을 지정하고 시스템이 직접 제시하도록 설계함.
- **사례:** “10달러보다 저렴한 램프”에 해당하는 제품과 가격, 장바구니 버튼을 모아 제공.
- **분류:** **명시적인 목표나 조건이 있는 탐색을 주로 지원하는 연구.**
- **해석상 주의:** 사용자가 구체적인 제품을 미리 결정할 필요는 없음. 따라서 모든 사용 상황을 100%로 단정하기보다, **‘최소한 요청할 목표·조건이 존재함을 전제’**한다고 표현하는 것이 정확함.

## [[Enabling Uniform|Savant]] - 목표를 자연어 명령으로 받아 실행
- **본문 근거:** “여백을 좁게 설정해 줘” 같은 자연어 명령을 UI 컨트롤과 값으로 연결하고, 필요한 스크린리더 조작을 자동 실행.
- **분류:** **원하는 작업이 정해진 상황을 중심으로 한 연구.**
- **해석상 주의:** 정확한 버튼 이름을 몰라도 명령 가능. 그러나 **조작 방법을 모르는 것과 무엇을 하고 싶은지 모르는 것은 다른 문제.**

# 0 < intent < 100: 목표·선호·질문을 구체화해야 하는 연구
## [[Morae]] - 이 문제를 가장 직접적으로 지적
- **핵심 문제:** 사용자의 최초 명령만으로는 원하는 결과를 결정하기에 충분하지 않으며, 사용자는 자신이 추가로 선택해야 한다는 사실조차 모를 수 있음.
	- **직접 근거 ① — 불충분한 조건:** 출발·도착 공항은 지정했지만 날짜·왕복 여부·좌석 등급은 지정하지 않은 요청, ‘최고의 초콜릿’처럼 평가 기준이 불명확한 요청 보고.
	- **직접 근거 ② — 드러나지 않은 선택지:** “가장 저렴한 탄산수”라는 요청에 같은 가격의 여러 맛이 존재하지만, 에이전트가 사용자에게 묻지 않고 하나를 선택하는 문제.
	- **직접 근거 ③ — 선택지 존재에 대한 무지:** 후속 인터뷰에서, 에이전트가 의도를 확인하지 않고 행동한 해당 상황의 **95%에서 참여자가 여러 유효한 선택지의 존재를 인지하지 못했다고 보고.** 전체 BVI 사용자에 대한 비율은 아님.
- **대응:** 결정 지점에서 자동화를 멈추고 대안의 차이를 설명하여, 사용자가 선호를 추가로 표현하도록 지원.
- **“페이지를 알기 전에는 자신의 요구를 완전하게 말하기 어렵다”는 주장에 가장 강한 근거.**
- 다만 Morae는 **이미 주어진 작업을 수행하면서 빠진 조건과 선호를 보완하는 연구**입니다. 무엇을 읽고 싶은지 자체를 발견하는 웹페이지 리딩 연구와는 차이가 있습니다. 또한 **‘말하지 않은 선호’가 반드시 ‘아직 형성되지 않은 선호’를 의미하지는 않습니다.**

## [[The Sky is the Limit]] - 정보를 접하면서 질문이 구체화되는 사례
- **직접 근거 ①:** 이미지가 무엇인지 질문 → 농산물 판매 차트임을 확인 → 포함된 범주를 질문 → 특정 지역의 데이터를 질문하는 단계적 상호작용 제시.
- **직접 근거 ②:** 큰 문서의 요약을 듣고, 그 안에서 관심 있는 주제를 선택한 뒤 해당 원문으로 이동하고 싶다는 참여자 요구 제시.
- **분류:** **초기에는 넓은 질문만 가능하지만, 정보를 얻으며 구체적인 질문과 읽을 대상을 선택하는 상황에 해당.**
- 요약의 역할을 ‘원문을 대체하는 답변’뿐 아니라 **‘다음에 무엇을 읽을지 결정하는 지원’**으로 설정할 근거.
- **범위:** 웹페이지 전용 연구가 아닌 생산성 애플리케이션 연구이며, 위 사례는 주로 참여자의 요구와 기대에 관한 결과.

## [[Enabling Uniform|Savant]] - 관련은 있지만 구분해야 하는 모호성
- **본문 근거:** “선택된 글자를 지워 줘”가 삭제인지 잘라내기인지 모호하면 선택지를 제시하여 확인.
- **판단:** 명령 해석의 모호성을 다루는 근거는 있음.
- **한계:** 사용자가 원하는 것을 알고 있지만 표현만 모호한 경우일 수 있으므로, **‘목표가 아직 형성되지 않았다’는 근거로 쓰기는 어려움.**

# intent 0%: 특정 대상을 정하기 전 둘러보는 상태
## [[Slide Gestalt]] - BVI의 ‘개요 파악 후 선택적 읽기’에 가장 가까운 근거
- **문제 지적:** 순차 읽기와 반복되는 슬라이드 요소로 인해 전체 구조와 주제의 경계를 파악하기 어려운 문제 보고.
- **접근:** 슬라이드 묶음의 계층 구조를 추출하여, 상위 섹션에서 하위 내용으로 이동하는 탐색 지원.
- **직접 관찰:** 참여자 5명이 먼저 전체 섹션을 훑은 뒤 세부 내용으로 이동. P5는 섹션·하위 섹션을 오가며 선택적으로 상세 내용을 읽음.
- **결과:** 정해진 시간 동안 읽은 슬라이드 수가 평균 **19.4개에서 29.3개**로 증가.
- **분류:** **특정 정보를 미리 지정하지 않아도 시작할 수 있는 훑어보기 지원.**
- **“무엇이 있는지 먼저 알아야 무엇을 읽을지 선택할 수 있다”는 설계 논리를 뒷받침.**

## [[EyeFormer]] - 특정 탐색 타깃이 없는 시선 행동의 근거
- **직접 근거:** 모델의 적용 대상으로 **free-viewing tasks**를 명시.
- **추가 근거:** GazeFormer와 비교하면서, free-viewing에는 사전 지정된 탐색 타깃이 없다고 설명.
- **분류:** **특정 탐색 타깃이 주어지지 않은 관찰 조건이라는 점에서 0% 범주와 연결 가능.**
- **중요한 한계:** BVI의 웹 리딩이나 목표 형성을 연구한 논문은 아님. **시선이 향하는 순서가 BVI에게 유용한 읽기 순서이거나, 디자이너 의도라는 사실을 검증하지도 않음.**
- 따라서 EyeFormer는 **초기 탐색에 제시할 정보 순서를 만드는 기술적 후보**로는 연결할 수 있지만, 그 순서의 유용성은 별도 검증이 필요합니다.
- **The Sky is the Limit**의 문서 구조·내용 개요에 대한 요구 역시 이 범주에 연결할 수 있습니다. 다만 참여자에게 사전 목표가 없었다고 확인한 연구는 아니므로 **간접 근거**로 사용하는 것이 적절합니다.
