	네가 하려는 연구를 구체적으로 이해했어. 최신 미팅자료와 추가 논문들을 비교한 뒤에도, 현재의 model papers 2편과 technical references 3편을 유지하는 것을 추천해. 교체해야 할 근거는 없어.
	다만 현재 다섯 편이 연구에 가장 가까운 선행연구를 모두 포함하는 것은 아니야. 추가 자료 중 Aural Glancing과 In-Page Navigation은 별도로 중요하게 비교해야 할 논문이야. 이것은 model paper를 교체해야 한다는 뜻과는 달라.
	아래에서 네 연구를 어떻게 이해했는지, 기존 구성을 유지하는 이유, 대안 논문으로 바꾸지 않는 이유를 구분해서 설명할게.

# 1. 내가 이해한 네 연구

최신 미팅자료의 19–27p와 39–40p를 기준으로 보면, 연구 질문은 다음과 같아.

> **읽을 대상이 아직 명확하지 않은 BVI 사용자가 웹페이지를 탐색할 때, 시각적 강조와 콘텐츠의 구조적·의미적 관계를 반영한 그룹 탐색 순서를 제공하면, 기존 방식보다 적은 노력으로 관심 정보를 발견하고 내용을 이해할 수 있는가?**

이 연구에는 서로 구분해야 하는 세 가지 설계가 있어.

|설계 대상|네 연구에서 결정할 내용|
|---|---|
|**그룹 구성**|어떤 콘텐츠를 하나의 의미 있는 탐색 단위로 묶을 것인가|
|**그룹 간 순서**|어느 그룹에서 시작하고, 다음에 무엇을 탐색하도록 추천할 것인가|
|**이동·읽기 상호작용**|사용자가 명령했을 때 해당 그룹으로 이동하고, 기존 스크린리더로 읽기와 조작을 이어가게 할 것인가|

여기서 **핵심 연구 기여로 삼으려는 것은 그룹 간 추천 탐색 순서와 그 사용자 효과**로 이해했어. 그룹화와 이동 기능은 그 순서를 제공하고 평가하기 위한 기반이고.

시스템은 다음처럼 동작하는 것이지.

1. LLM이 페이지의 텍스트와 시각적·구조적 단서를 분석.
2. 관련 콘텐츠를 의미 있는 그룹으로 묶음.
3. 시각적 강조와 그룹 간 관계를 고려해 추천 순서를 생성.
4. 사용자가 시작·다음 그룹·이전 그룹 명령을 실행하면 해당 그룹의 시작점으로 이동.
5. 그 위치에서 기존 스크린리더로 내용을 읽고 링크·버튼·옵션 등을 조작.

중요한 것은 **콘텐츠의 실제 배치를 추천 순서대로 바꾸지 않는다는 점**이야. 기본 연속 읽기 순서도 유지하고, 확장 프로그램의 그룹 이동 명령에만 추천 순서를 적용해.

예를 들어 상품 페이지에서 가격 영역이 시각적으로 가장 두드러져도, 제품을 이해한 뒤 가격을 확인하는 편이 자연스럽다면 설명을 먼저 제시할 수 있어. 다만 **어떤 상황에서 시각적 강조보다 맥락을 우선할지는 아직 개발할 설계 기준**이야. 미팅자료도 이를 남은 과제로 명시하고 있어.

평가 역시 두 효과를 구분하려고 해.

- **전체 시스템 효과:** 원본 페이지 탐색과 제안 시스템을 이용한 탐색의 차이.
- **순서의 효과:** 그룹·콘텐츠·조작은 같게 유지하면서, 원래 읽기 순서에 따른 그룹 이동과 추천 순서에 따른 그룹 이동의 차이.

이 구분은 적절해. 그래야 결과가 좋아졌을 때 **그룹화 덕분인지, 바로 이동할 수 있어서인지, 추천 순서 덕분인지**를 구별할 수 있어.

또한 `designer intent`는 디자이너의 실제 심리적 의도를 확인하겠다는 뜻이 아니라, **페이지의 강조와 조직에서 추론한 전달 의도를 탐색 단서로 사용하는 것**으로 이해했어. 따라서 연구의 최종 검증 대상도 의도 추론의 진위 자체보다는 **그 단서로 만든 탐색 방식의 유용성**이야.

# 2. 최종 선정 판단

|구분|논문|판단|유지하는 핵심 이유|
|---|---|---|---|
|Model paper 1|**Slide Gestalt**|**유지. 가장 핵심적**|시각적·텍스트적 관계를 추출해 비시각적 탐색 구조로 제공하고 사용자 효과를 평가하는 전체 접근이 가까움|
|Model paper 2|**Task Mode**|**유지**|LLM의 도움을 받되 사용자가 웹 탐색을 통제하는 상호작용과 평가를 참고하기 적합|
|Technical reference|**From Cluttered to Clear**|**유지**|의미 있는 그룹·라벨·HTML 구조와 스크린리더 탐색의 연결, 콘텐츠 보존 및 평가에 도움|
|Technical reference|**SaIL**|**유지**|시각적 분석 결과를 DOM 요소와 실제 탐색 진입점으로 연결하는 직접적인 참고 사례|
|Technical reference|**Learning Visual Importance**|**유지**|시각적 중요도를 사람의 판단·행동에 근거해 정의하고 예측하는 방법론을 제공|

**Model paper를 하나만 선택해야 한다면 Slide Gestalt를 선택하면 돼.** 두 편이 가능하다면 현재처럼 Slide Gestalt와 Task Mode를 유지하는 편이 좋아.

단, 두 편의 위상은 같지 않아.

- **Slide Gestalt:** 전체 연구 접근의 주된 모델.
- **Task Mode:** 사용자 통제와 LLM 보조 탐색 설계·평가의 보완 모델.

현재 16p의 Role 설명도 이미 이 차이를 잘 반영하고 있어.

# 3. Slide Gestalt를 유지해야 하는 이유

Slide Gestalt는 대상이 웹페이지가 아니라 슬라이드이지만, **네 연구의 중심 논리와 가장 잘 맞는 논문**이야.

**첫째, 접근성 문제를 개별 요소보다 요소 간 관계에서 찾는다.**

Slide Gestalt는 개별 슬라이드 요소에 접근할 수 있어도, 슬라이드 간 반복·분할·진행 관계가 드러나지 않으면 덱 전체를 이해하고 탐색하기 어렵다고 봐.

네 연구도 콘텐츠가 읽히는지에 그치지 않고, **페이지가 무엇을 강조하고 콘텐츠들이 어떻게 연결되어 있는지를 탐색에 활용할 수 있는지**를 묻고 있어.

**둘째, 분석 결과를 실제 탐색 구조로 변환한다.**

Slide Gestalt의 기여는 구조를 검출하는 것에서 끝나지 않아. 검출 결과를 section·subsection, 구조 설명, 이동 가능한 heading으로 제공해.

네 연구에서도 시각적 강조나 관계를 분석하는 것만으로는 충분하지 않고, 그것을 그룹과 이동 순서로 바꿔야 해. 이 전환을 설계하는 전체 접근이 유사해. — 원문 §4–5

**셋째, 기술적 분석과 사용자 효용을 함께 평가한다.**

Slide Gestalt는 구조 추출 성능과 함께, BVI 사용자가 얼마나 잘 훑어보고 정보를 찾는지를 평가해. 이는 네 연구에서 **분석·그룹화 결과의 타당성과 실제 탐색 효과를 구분해 보는 방식**에 참고가 돼. — 원문 §6–7

다만 Slide Gestalt가 네 연구를 그대로 수행한 것은 아니야.

- 이미 순서가 있는 슬라이드 덱의 구조를 추출함.
- 웹페이지에 새로운 그룹 탐색 순서를 제안하는 연구는 아님.
- 목표 불명확성을 독립적인 연구 조건으로 체계화한 것도 아님.

그렇지만 **model paper는 연구 질문이 완전히 같은 논문일 필요가 없어.** 현재처럼 “관계를 추출하고, 탐색 인터페이스로 전달하고, 사용자 효과를 평가하는 접근”의 모델로 쓰는 것은 정확해.

# 4. Task Mode를 유지해도 되는 이유

Task Mode는 현재 선정 중에서 가장 검토할 여지가 있는 논문이었어. **명시된 목표를 입력받는다는 점이 네 연구와 다르기 때문**이야.

그래도 현재 부여한 역할을 기준으로는 유지하는 것이 타당해.

**첫째, LLM이 사용자의 탐색을 보조하는 방식이 가깝다.**

Task Mode는 사용자가 원하는 일을 전부 대신 수행하는 에이전트가 아니라, 관련 정보를 드러내 사용자가 직접 탐색하고 판단하게 해.

네 시스템도 LLM이 그룹과 순서를 제안하지만, 실제 이동·읽기·선택은 사용자가 수행해. 따라서 **AI의 추천과 사용자의 직접 탐색을 어떻게 결합할지**를 참고하는 데 적합해.

**둘째, 기존 웹페이지와 스크린리더 사용 흐름에 기능을 더한다.**

별도의 완전히 새로운 읽기 도구를 학습하게 하기보다 기존 탐색에 LLM의 도움을 결합한다는 점이 네 방향과 맞아. 다만 Task Mode는 콘텐츠를 숨길 수 있고, 네 시스템은 콘텐츠를 유지하며 이동 경로를 제공한다는 차이가 있어.

**셋째, 통제감과 신뢰를 실제 사용자 경험의 문제로 다룬다.**

Task Mode에서는 사용자가 필터링 결과를 원본과 비교하고, 맥락이나 정보가 빠졌을 가능성을 우려하는 행동이 나타나.

네 시스템은 내용을 삭제하지 않더라도, 추천 경로에 들지 않은 영역이 사용자에게 덜 드러날 수 있어. 따라서 **“추천만 따라가도 되는가”, “언제 원래 탐색으로 돌아가는가”** 같은 문제를 검토하는 데 참고할 수 있어. — 원문 §5–6

**넷째, 평가를 참고할 수 있다.**

수행 시간, 주관적 부담, 정보 찾기의 용이성, 통제감·신뢰를 함께 다룬다는 점이 유용해.

다만 목표가 정해진 과제의 성공률·완료 시간을 네 연구에 그대로 가져오면 안 돼. 네 상황에서는 **관심 정보 발견까지의 비용, 탐색한 내용의 이해, 발견한 정보의 유용성**처럼 목표 불명확성을 반영한 평가가 필요해. 최신 미팅자료 24p는 이미 그 방향으로 작성되어 있어.

따라서 판단은 다음이야.

> **Task Mode를 ‘목표 없는 탐색의 모델’로 쓰는 것은 부적절하지만, ‘사용자 통제를 유지하는 LLM 보조 웹 탐색과 평가의 모델’로 쓰는 것은 적절해. 현재 자료는 후자로 쓰고 있으므로 유지하면 돼.**

# 5. Technical references 3편을 유지하는 이유

## From Cluttered to Clear: 의미 구조와 실제 탐색 경험의 연결

이 논문은 다음에 도움이 돼.

- 관련 콘텐츠를 의미 있는 heading·section으로 조직.
- 과도하거나 불명확한 라벨을 개선.
- HTML 변경이 스크린리더 탐색에 미치는 영향 확인.
- 콘텐츠 누락·변경 점검.
- 자동 접근성 검사와 사용자 경험 평가를 병행.

네 연구는 HTML 전체를 재생성하지 않으므로 전체 구현을 따라 할 필요는 없어. **그룹·라벨의 설계와 탐색 경험의 검증을 가져오는 것**이면 충분해.

최신 17p에는 “원본 콘텐츠와 레이아웃을 유지하면서 이 교훈을 적용한다”고 명시되어 있어. 이 수정으로 적용 범위도 명확해졌어.

## SaIL: 시각적 영역에서 탐색 진입점으로의 연결

SaIL은 네 연구의 구현 단계에 특히 직접적으로 연결돼.

- 시각적 분석에서 얻은 영역을 HTML 후보 요소와 연결.
- 선택한 요소를 기존 스크린리더가 접근할 수 있는 지점으로 제공.
- 의미 있는 영역의 시작점에 진입점을 두는 문제 검토.
- 일부 영역만 선택했을 때 생기는 탐색 범위의 불일치 검토.

하지만 SaIL은 **랜드마크 선정의 saliency 순위가 유용한 그룹 탐색 순서라고 검증한 논문은 아니야.** 네 자료에 “그룹 간 추천 순서는 별도로 설계·평가한다”고 적은 것은 정확해.

## Learning Visual Importance: ‘중요하다’를 무엇으로 정의할지에 대한 근거

Learning Visual Importance는 네 시스템과 대상 도메인이 같지는 않지만, 기술적 역할이 분명해.

- 사람의 명시적 중요도 판단과 탐색 행동을 구분.
- 도메인별 데이터를 이용해 중요도를 예측.
- 예측 결과를 사람의 반응과 비교.
- 중요도 예측 자체의 성능과 응용에서의 유용성을 따로 평가.

네 연구에서 “크고 눈에 띄니까 중요하다”는 직관만 사용하는 것을 넘어, **시각적 중요도를 어떻게 정의하고 검증할 수 있는지** 생각하게 해주는 논문이야.

현재 LLM을 쓸 계획이라고 해서 이 논문의 FCN을 구현해야 하는 것은 아니야. **중요도 추정의 방법론을 참고하는 것**도 충분히 타당해.

단, 사람에게 중요하게 지각되는 영역, 디자이너의 실제 의도, BVI에게 유용한 읽기 순서는 서로 같지 않아. 최신 17p의 **“one cue”, “adaptation and validation for web pages”**는 그 한계를 적절하게 반영해.

# 6. 추가 논문 중 가장 가까운 대안들을 검토한 결과

## ① Aural Glancing — 가까운 선행연구지만, Task Mode를 반드시 대체할 필요는 없음

From Screen Reading to Aural Glancing은 추가 자료 중 **네 탐색 인터랙션과 가장 가까운 논문 중 하나**야.

공통점이 상당해.

- 개별 요소보다 페이지의 주요 section을 탐색 단위로 사용.
- 중요한 section을 우선적으로 제공.
- 사용자가 명령하면 해당 section에 직접 접근.
- 기존 스크린리더 접근을 보완.
- 우선 제공되지 않은 section도 추가로 확인할 수 있게 설계.

따라서 네 연구를 **“중요한 그룹을 먼저 보여주고 이동하게 하는 최초의 방식”**으로 설명하면 안 돼. 이 선행연구와 차이를 밝혀야 해.

그럼에도 model paper 교체를 추천하지 않는 이유는 두 가지야.

**첫째, 우선순위의 근거가 다르다.** 이 논문은 일반적인 쇼핑 과제를 수행하는 맥락에서, crowdsourcing으로 페이지 section의 중요도를 순위화해. 네 연구는 현재 페이지의 시각적 강조와 콘텐츠 관계를 해석하고, 목표가 명확하지 않은 상황의 탐색 순서를 설계하려고 해.

**둘째, 제안 시스템의 평가 범위가 다르다.** 논문에는 BVI 사용자를 포함한 형성 연구와 crowd ranking 연구가 있지만, DASX 자체의 성능 개선 평가는 **KLM-GOMS 기반의 예비 분석적 평가**야. 완성된 DASX를 대상으로 한 BVI 비교 사용자 실험과 동일하게 보면 안 돼. — 원문 §5–6

그래서 이 논문의 가장 적절한 역할은 다음이야.

> **그룹 단위 우선 탐색과 직접 접근에 대한 핵심 선행연구이자 인터랙션 참고.**

Task Mode가 맡는 **LLM 보조 탐색의 통제·신뢰·사용자 평가 역할**을 완전히 대신하지는 않아. 현재 두 model paper의 역할을 유지하면서 이 논문을 별도로 비교하는 편이 더 좋아.

## ② In-Page Navigation — 구현 참고 가치는 높지만, 현재 구성을 교체해야 할 정도는 아님

In-Page Navigation Aids for Screen-Reader Users with Automatic Topicalisation and Labelling은 다음 과정이 네 연구와 가까워.

1. 웹페이지의 텍스트를 주제별로 분할.
2. 각 구간에 라벨 생성.
3. 원본 HTML에서 해당 구간을 찾음.
4. heading과 내부 링크를 삽입해 이동 지원.

특히 **그룹화 결과를 실제 페이지에 연결하는 구현**과 다음 사용자 피드백이 유용해.

- 구간을 구별하지 못하는 반복적인 라벨.
- 너무 길거나 어려운 heading.
- 재실행할 때 달라지는 생성 결과.
- 처리 시작·완료 피드백의 부재.
- 기능을 켜고 끄는 방법.
- 기존 스크린리더 명령과의 통합.

다만 주된 대상은 **긴 텍스트의 주제 분할과 라벨링**이야. 논문도 이미지·표·폼·버튼 등을 현재 분석 범위 밖의 한계로 명시해. 시각적 강조를 해석해 새로운 탐색 순서를 추천하는 연구는 아니야. — 원문 §5.2, §5.6, §6.4

따라서 **구현할 때 추가로 참고할 가치가 매우 높지만**, From Cluttered to Clear가 담당하는 페이지 전체의 의미 구조·상호작용 요소·콘텐츠 보존 평가를 전부 대신하는 것은 아니야.

**현재 세 technical references를 유지해도 돼.** 다만 구현 단계의 읽기 목록에서는 이 논문을 높은 우선순위에 두는 것을 추천해.

## ③ Navigal — DOM 연결은 가깝지만, 목표와 인터페이스가 다름

Navigal은 자연어로 원하는 컨트롤을 지정하면, 원본 DOM 요소와 연결된 별도 인터페이스를 생성해. 원본 요소로 이동해 결과를 확인할 수 있다는 점도 있어.

따라서 **생성 결과와 원본 요소의 연결, 결과 검증, DOM 변경 대응**은 참고할 수 있어.

그러나 핵심은 **사용자가 지정한 목표에 맞춘 컨트롤 인터페이스 구성과 재사용**이야. 네 연구의 “목표가 불명확한 상황에서 원본 페이지 안의 콘텐츠 그룹을 탐색”하는 방식과는 달라.

현재 역할을 기준으로 Task Mode나 SaIL을 대체해야 할 근거는 없어.

참고로 첨부본은 파일명과 달리 본문에 **Anonymous Author(s), Manuscript submitted to ACM, 임시 DOI**가 표시되어 있어. 이 파일만으로 “CHI ’27 출판 논문”이라고 표기해서는 안 돼. 이것은 내용의 참고 가치를 부정하는 것이 아니라 서지 상태를 구분하자는 뜻이야.

## ④ Morae — 불명확한 선호를 다루지만, 네 연구의 불명확성과는 다름

Morae는 자동화 중 중요한 선택 지점에서 멈추고 사용자에게 선택권을 돌려줘.

하지만 여기서 불명확한 것은 주로 **주어진 과제를 수행하는 데 필요한 선호나 선택 조건**이야. 예를 들어 구매 목표는 있지만 같은 가격의 여러 상품 중 무엇을 선택할지는 정해지지 않은 상황이지.

네 연구는 **어떤 콘텐츠에 관심을 둘지 탐색하면서 정하는 상황**이 중심이야. 과제를 대신 수행하는 에이전트도 아니고.

따라서 사용자 선택권과 모호성에 대한 참고는 가능하지만, 현재 Task Mode보다 네 시스템의 상호작용 역할에 더 적합하다고 보기는 어려워.

## ⑤ EyeFormer — ‘순서’를 예측한다는 이유로 교체하면 안 됨

EyeFormer는 시선 위치와 지속시간을 포함하는 scanpath를 예측해. 그러므로 중요도 맵만 예측하는 논문보다 네 “순서” 연구에 더 가까워 보일 수 있어.

하지만 다음은 서로 다른 문제야.

- 사람들이 시각적으로 어디를 어떤 순서로 보는가.
- BVI 사용자가 음성으로 내용을 이해하기 위해 어떤 콘텐츠 그룹을 먼저 읽는 것이 좋은가.

시선은 작은 단위의 반복 방문이나 빠른 이동을 포함할 수 있지만, 콘텐츠 그룹의 음성 탐색은 맥락 유지와 이동 비용을 함께 고려해야 해.

네 연구가 **시선 경로를 비시각적 탐색 경로로 변환하는 방식**을 선택한다면 EyeFormer의 중요성이 커지겠지만, 현재 계획은 그렇지 않아. 지금 Learning Visual Importance를 대체할 필요는 없어.

# 8. 유지하되, 연구의 차별성을 설명할 때는 이 부분을 명확히 해야 함

현재 다섯 편을 유지하는 것은 타당하지만, 이를 근거로 다음을 새로운 기여라고 주장하면 부족해.

- 콘텐츠를 그룹으로 묶는다.
- 중요한 영역에 빠르게 이동한다.
- 기존 스크린리더에 기능을 추가한다.
- LLM으로 탐색을 돕는다.

이 요소들은 첨부한 여러 선행연구에 이미 나타나.

네 연구에서 구체적으로 설계하고 검증할 부분은 다음의 **결합**이야.

> **목표가 불명확하거나 부분적으로만 정해진 탐색 상황에서, 시각적 강조와 콘텐츠 간 관계를 함께 사용해 맥락을 고려한 그룹 탐색 순서를 만들고, 그 순서 자체가 발견 비용과 이해에 미치는 효과를 평가하는 것.**

그렇다고 이 결합의 신규성이 이번 자료만으로 확정되는 것은 아니야. 다만 **현재 model paper 선정이 적절한가**라는 질문과 **이 조합이 충분히 새로운 연구 기여인가**라는 질문은 구분해야 해.

현재 구성은 전자에 잘 답해. 후자를 설명할 때는 Aural Glancing의 우선 영역 접근, In-Page Navigation의 주제별 탐색 지원, 문맥 기반 우선 읽기 연구와도 비교해야 해.

**추천 구성은 그대로야.**

- **Model papers:** Slide Gestalt + Task Mode.
- **Technical references:** From Cluttered to Clear + SaIL + Learning Visual Importance.
- **별도로 중요하게 비교할 선행연구:** Aural Glancing, In-Page Navigation.
- **Model paper를 하나로 줄여야 한다면:** Slide Gestalt.

기존 선정을 바꾸는 것보다, **각 논문에서 가져오는 역할과 네가 새로 검증할 부분을 지금처럼 분명히 유지하는 것이 더 중요해.**
