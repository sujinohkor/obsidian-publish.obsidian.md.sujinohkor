	모델 페이퍼는 ① CHI’23 Slide Gestalt, ② UIST’17 Learning Visual Importance를 추천합니다. 한 편만 선정한다면 Slide Gestalt입니다.

두 논문의 역할은 다릅니다.

- **Slide Gestalt:** 시각적 구성에 담긴 구조를 추출하고, 이를 BVI 사용자의 비시각 탐색에 연결하는 **연구 전체의 모델**
- **Learning Visual Importance:** 시각적 강조를 요소별 중요도로 계산하는 **핵심 기술 접근의 모델**

다만 **두 논문을 결합하는 것만으로 연구가 완성되지는 않습니다.** 시각적 중요도와 구조를 **이해하기 좋은 음성 탐색 순서로 변환하는 방법**, 그리고 **목표가 불명확한 사용자에게 실제로 도움이 되는지 검증하는 것**이 수진님 연구의 중심 과제로 남습니다.

아래 선정은 첨부 논문의 방법·평가·한계를 기준으로 한 판단입니다. 논문이 보여준 결과와 수진님 연구에 적용하기 위한 제안을 구분했습니다.

# 1. 수진님 연구를 이해한 기준

앞으로 이 연구를 논의할 때 다음 정의를 기준으로 삼겠습니다.

> **읽을 대상이 아직 명확하지 않은 BVI 사용자를 위해, 웹페이지의 시각적 강조와 구조에서 추론한 디자이너의 전달 의도를 탐색 단서로 활용하고, 이를 반영한 읽기 순서가 탐색 효율과 이해를 개선하는지 연구하는 것.**

이 정의에서 중요한 것은 세 가지입니다.

|구분|연구에서 다루는 질문|
|---|---|
|**추론 근거**|크기·배치·대비·그룹화·제목·내용 관계에서 무엇을 추론할 수 있는가?|
|**음성 탐색으로의 변환**|추론한 중요도와 구조를 어떤 단위와 순서로 제시해야 하는가?|
|**사용자 이점**|목표가 불명확하거나 부분적으로 정해진 사용자가 읽을 대상을 발견하고 내용을 이해하는 데 도움이 되는가?|

**“Designer intent와 user intent가 다를 수 있다”는 사실은 접근을 폐기할 이유가 아니라, 적용 조건과 실패 조건을 검증해야 할 이유**로 이해했습니다.

또한 `Intent 0% / 0–100% / 100%`는 현재 단계에서는 **탐색 목표의 구체성을 설명하는 개념적 구분**입니다. 논문에서 검증된 수치 척도처럼 사용하면 안 됩니다. 특히 다음은 구분해야 합니다.

- **원하는 것이 아직 정해지지 않음**
- 원하는 것은 있지만 **어떻게 표현해야 할지 모름**
- 원하는 것은 분명하지만 **페이지 어디에 있는지 모름**

수진님 연구의 주된 대상은 첫 번째와 부분적으로 두 번째입니다. 세 번째만 해결하는 논문은 직접적인 모델로 보기 어렵습니다.

# 2. 모델 페이퍼 ① — Slide Gestalt, CHI’23

_Slide Gestalt: Automatic Structure Extraction in Slide Decks for Non-Visual Access_

**선정 이유: “시각적 구성의 의미를 비시각적 탐색 지원으로 연결한다”는 연구 논리가 가장 가깝습니다.**

이 논문은 슬라이드의 개별 요소를 읽을 수 있게 만드는 데서 더 나아가, 저자가 사용한 시각적·텍스트적 패턴을 통해 **덱 전체의 구조와 구성 목적을 드러냅니다.**

예를 들어 다음과 같은 패턴을 구분합니다.

- **Divider:** 구간 전환을 나타내는 슬라이드
- **Build:** 내용을 조금씩 추가하며 전개하는 슬라이드 묶음
- **Topic split:** 하나의 주제를 여러 슬라이드로 나눈 묶음

스크린리더가 이를 단순히 순서대로 읽으면, 사용자는 반복되는 내용이나 짧은 구분 슬라이드의 의미를 스스로 복원해야 합니다. Slide Gestalt는 이 관계를 명시적인 계층과 설명으로 제공합니다.

**실제 방법**

|단계|논문의 구현|수진님 연구에 가져올 부분|
|---|---|---|
|요소 추출|텍스트·이미지·도형·위치·슬라이드 이미지 추출|웹페이지의 DOM, 화면상의 위치, 시각적 속성, 내용 추출|
|관계 분석|시각·텍스트 임베딩과 슬라이드 간 대응 관계 계산|요소 간 시각적 그룹과 의미적 관계 분석|
|구조 추출|규칙과 정렬 결과를 이용한 섹션·하위 그룹 식별|페이지→섹션→콘텐츠 단위의 탐색 구조 구성|
|비시각적 표현|전체 개요, 섹션·하위 섹션 설명, 개별 요소 목록|개요→추천 시작점→선택한 영역의 상세 내용|
|평가|구조 추출 평가와 BVI 사용자 평가를 분리|추론 정확도와 탐색 효과를 별도로 검증|

근거 위치는 **§3–5, Figure 3–4, §6–7**입니다.

**특히 모델로 삼을 부분은 연구 과정입니다.**

논문은 BVI 독자뿐 아니라 **슬라이드 작성자도 인터뷰**하고, 100개 덱을 분석해 구성 패턴을 정리했습니다. 수진님도 designer intent를 주장하려면 이러한 과정이 중요합니다.

예를 들어 웹 디자이너에게 다음을 확인할 수 있습니다.

- 사용자가 처음 알아차리길 기대한 내용
- 반드시 함께 이해해야 하는 요소
- 제목·이미지·설명의 관계
- 시각적으로 강조했지만 정보적 중요도는 낮은 요소

이 과정을 거치면 “크기가 커서 중요하다고 추정했다”에서 나아가, **시각적 근거와 의도 사이의 관계를 검증**할 수 있습니다.

**실제로 보여준 사용자 이점**

8명의 BVI 사용자가 참여한 평가에서 다음을 보고했습니다.

|지표|Slide Gestalt|비교 인터페이스|
|---|---|---|
|3분간 읽은 슬라이드 수|29.3개|19.4개|
|질문의 답을 찾는 시간|45.8초|96.9초|
|탐색 중 읽은 중복 요소 수|6.5개|20.6개|

비교 조건도 요소 설명과 슬라이드별 제목을 제공하는 접근 가능한 인터페이스였습니다. 따라서 **계층 정보가 추가로 주는 이점**을 살펴봤다는 점이 유용합니다.

단, 읽은 슬라이드 수가 많다는 사실 자체를 객관적 이해도 향상과 동일시하면 안 됩니다. 이해에 관한 주관적 평가와 탐색 지표를 구분해서 인용해야 합니다.

**수진님 연구에 그대로 적용할 수 없는 부분**

1. **슬라이드 덱의 순차성과 반복 패턴을 이용합니다.**  
    일반 웹페이지에서 동일한 구조 가정이 성립하지 않습니다.
    
2. **시각적 중요도에 따른 읽기 순서를 학습한 논문이 아닙니다.**  
    §5.4의 슬라이드 내부 요소 순서는 좌상단과의 거리를 기준으로 조정합니다.
    
3. **LLM으로 designer intent를 추론하지 않습니다.**  
    사전학습 임베딩, 정렬 알고리즘, 규칙 기반 처리 등을 결합합니다.
    
4. **목표 불명확성에 따른 효과 차이를 실험하지 않았습니다.**  
    Skimming을 포함하지만, 사용자를 수진님의 세 가지 intent 조건으로 나누어 검증한 것은 아닙니다.
    

**판정:** 연구의 문제 설정, 구조 추출, 탐색 인터페이스, 평가 설계를 본받을 **주 모델 페이퍼**입니다. 알고리즘 전체를 웹페이지에 그대로 옮기는 용도는 아닙니다.

# 3. 모델 페이퍼 ② — Learning Visual Importance, UIST’17

_Learning Visual Importance for Graphic Designs and Data Visualizations_

**선정 이유: “시각적 강조를 어떻게 계산 가능한 중요도로 바꿀 것인가?”에 가장 직접적으로 연결됩니다.**

이 논문은 그래픽 디자인과 데이터 시각화의 이미지에서 **상대적 중요도 맵**을 예측합니다. 단순한 색상 대비 같은 저수준 saliency뿐 아니라 제목·축 설명·데이터 영역처럼 요소의 역할과 관련된 중요도도 고려하는 문제 설정입니다.

**실제 방법**

- 입력: 디자인 또는 시각화의 비트맵 이미지
- 학습 데이터:
    - 그래픽 디자인: 사람들이 중요 영역을 표시한 GDI 주석
    - 데이터 시각화: 흐린 이미지의 일부를 클릭해 확인하는 BubbleView 데이터
- 모델: VGG-16 기반 Fully Convolutional Network
- 출력: 픽셀별 중요도 값
- 요소 수준 활용: 중요도 맵과 요소 영역을 겹쳐 요소별 점수 산출

논문에서는 요소 영역 내부의 **최댓값**을 사용해 중요도 순위를 계산하는 분석도 수행했습니다. 수진님 연구에서는 이 집계 방식 자체도 검토해야 합니다. 한 지점의 강한 강조가 큰 섹션 전체의 중요도를 대표하지 않을 수 있기 때문입니다.

근거 위치는 **Data Collection, Models for Predicting Importance, Evaluation of Model Predictions, Figure 6–9**입니다.

**수진님 연구에 가져올 부분**

|가져올 것|활용 방식|
|---|---|
|중요도를 연속적인 값으로 표현|각 요소·섹션의 상대적 강조 정도 계산|
|인간 주석을 이용한 검증|시스템이 판단한 강조 순위와 사람의 판단 비교|
|픽셀→요소 수준 변환|중요도 맵을 실제 읽을 수 있는 DOM 요소와 연결|
|크기·위치 변화에 대한 검증|같은 내용의 레이아웃을 바꿨을 때 강조 판단 변화 확인|
|자연 이미지 saliency와의 비교|디자인 중요도에 특화된 신호가 필요한지 검증|

**가장 중요한 제한: 이 논문의 정답은 ‘디자이너의 실제 의도’가 아닙니다.**

GDI는 관찰자의 중요 영역 주석이고, BubbleView는 관찰 행동의 대리 지표입니다. 따라서 다음을 구분해야 합니다.

|개념|의미|
|---|---|
|관찰자가 지각한 중요도|무엇을 중요하게 받아들이는가|
|시각적 주의|어디를 보거나 확인하는가|
|디자이너의 전달 의도|무엇을 알아차리고 이해하도록 만들려 했는가|
|BVI 사용자의 탐색 효용|무엇을 먼저 들었을 때 탐색에 도움이 되는가|

이 네 가지는 관련될 수 있지만 동일하지 않습니다.

논문은 그래픽 디자인 요소의 예측 순위와 인간 주석 사이에 평균 Spearman 상관 **0.56**을 보고합니다. 유용한 신호이지만, 정확한 순서를 보장하는 결과는 아닙니다. 텍스트 편향과 요소 경계 처리의 한계도 논의합니다.

**추가로 남는 문제**

- 주된 학습·평가 대상이 그래픽 디자인과 시각화이므로 **일반 웹페이지로의 전이 검증 필요**
- 중요도 맵은 시간적 순서를 담지 않으므로 **읽기 순서 생성 방법 필요**
- BVI 사용자 평가가 없으므로 **음성 탐색 효과의 별도 검증 필요**

**판정:** 시각적 중요도를 추정하고 검증하는 **두 번째 모델 페이퍼**입니다. 기존 가중치를 그대로 사용하는 것보다, **중요도의 정의·주석·평가 방법을 가져오는 가치**가 큽니다.

# 4. 왜 이 두 편인가?

|연구 구성 요소|Slide Gestalt|Learning Visual Importance|수진님이 새로 해결할 부분|
|---|---|---|---|
|시각적 강조 추정|중심 기능 아님|직접 다룸|웹페이지에서 타당성 검증|
|내용 간 구조·관계|직접 다룸|중심 기능 아님|웹페이지에 맞는 구조 표현|
|BVI 비시각 탐색|직접 다룸|다루지 않음|강조와 구조를 결합한 탐색 순서|
|목표 불명확성|조건별 검증 없음|조건별 검증 없음|목표 상태에 따른 효과 검증|
|디자이너 의도 검증|작성자 조사로 구성 패턴 파악|관찰자 중요도 중심|실제 의도와 추론 결과의 관계 검증|

**두 편이 각각 ‘구조를 통한 비시각 탐색’과 ‘시각적 중요도 추정’을 제공한다는 점이 선정 이유입니다.**

다만 발표에서 “이 두 연구를 결합한다”까지만 말하면 약합니다. **결합 과정에서 발생하는 음성 순서 설계 문제와 목표 불명확성의 효과**를 연구 질문으로 분명히 제시해야 합니다.

# 5. 반드시 참고할 기술·상호작용 논문

## ① From Cluttered to Clear — ASSETS’25

_From Cluttered to Clear: Improving the Web Accessibility Design for Screen Reader Users in E-commerce With Generative AI_

**가장 먼저 추가로 볼 기술 참고이자, 차별성을 설명할 때 반드시 비교할 선행연구입니다.**

- **가져올 기술:** DOM 추출, 구조 단위 분할, LLM을 이용한 HTML 재구성, heading·label 개선, 원문과 결과의 내용 보존 검사
- **가져올 상호작용:** 상품명·설명·리뷰 등을 이해 가능한 순서로 구성
- **핵심 근거:** §5, §7.4–7.5, Appendix A
- **연구와의 차이:** 디자이너의 시각적 강조를 명시적으로 추정하는 것이 아니라, 스크린리더 사용에 적합한 구조로 재구성하는 접근

**이 논문을 과소평가하면 안 됩니다.** 평가에는 엄격한 특정 상품 찾기 목표 없이 자유롭게 둘러보는 상황도 포함됩니다. 따라서 “기존 연구는 명확한 목표가 있는 경우만 다뤘다”는 주장은 성립하지 않습니다.

다만 탐색 시간의 정량 비교는 자유 탐색 전체가 아니라, 상품 상세 페이지에서 **상품 설명을 찾는 행동**에 집중했습니다. 수진님은 여기서 더 나아가 **읽을 대상의 발견, 목표 구체화, 페이지 이해**를 평가할 수 있습니다.

구현 시에는 두 가지를 보완해야 합니다.

- 논문이 보고한 페이지 처리 시간은 **1–5분**으로, 즉시 탐색 지원에는 부담
- 전체 의미 유사도가 높아도 개별 가격·조건·링크의 보존까지 보장되지는 않으므로 **요소별 대응 검사 필요**

## ② In-Page Navigation Aids — TACCESS’24

_In-Page Navigation Aids for Screen-Reader Users with Automatic Topicalisation and Labelling_

**“읽을 수 있는 의미 단위와 이동 지점을 만드는 기술”에 유용합니다.**

- **가져올 기술:** 문장 임베딩 기반 주제 분할, 구간별 제목 생성, heading과 내부 링크 삽입
- **실제 구성:** BERT 계열 임베딩을 이용한 분할, 두 번째 개발 단계에서 OpenAI를 이용한 제목 생성
- **핵심 근거:** §4.1–4.2, §5.2, §6.3–6.4
- **적용 위치:** 기존 제목이 부족한 페이지에서 탐색 단위와 설명 가능한 라벨 생성

한계도 분명합니다.

- 텍스트 중심으로 처리하며 이미지·표·폼·버튼은 분석 대상에서 제외
- 시각적 강조나 디자이너 의도 추론 없음
- 생성한 제목의 반복·모호성 문제
- 두 번째 사용자 평가는 질적 평가 중심이며, 비교 실험으로 시간 단축을 입증한 것은 아님

**추천 역할:** 구조만 제공하는 비교 조건과, 탐색용 heading 생성 모듈.

## ③ Accessible Skimming — UIST’12

_Accessible Skimming: Faster Screen Reading of Web Pages_

**“짧게 듣다가 관심이 생기면 그 위치의 원문으로 들어가는 방식”을 가져올 가치가 큽니다.**

- **가져올 기술:** 문장 의존 관계와 분류기를 이용한 구절 추출
- **가져올 상호작용:** 읽던 위치를 유지하면서 skimming과 원문 읽기 사이 전환
- **핵심 근거:** _Overview of Our Approach — Interface_, _Skimming Algorithm_, _User Study_
- **적용 위치:** 추천 순서에 따라 영역을 짧게 소개하고, 선택하면 자세히 읽는 기능

특히 이 논문은 **요약문을 별도로 읽는 것과 skimming 인터페이스를 사용하는 것을 구분**합니다. 수진님도 짧은 요약을 제공하는 데서 끝내지 않고, 요약·섹션·원문이 연결되도록 설계하는 것이 중요합니다.

주의할 점은 **압축에 따른 이해 손실**입니다. 실험에서 자동 skimming의 질문 정답률은 약 71%, 전문 읽기는 약 80%였습니다. 따라서 “더 짧게 들었으니 더 효율적”이라는 지표만으로 평가하면 안 됩니다.

**추천 역할:** 탐색 단계와 상세 읽기 단계의 연결, 속도–이해도 절충 평가.

## ④ From Screen Reading to Aural Glancing — ASSETS’14

_From Screen Reading to Aural Glancing: Towards Instant Access to Key Page Sections_

**“처음 무엇을 들려주고, 나머지는 어떻게 발견하게 할 것인가?”를 설계할 때 중요합니다.**

- **가져올 상호작용:** 주요 섹션 목록, 나머지 섹션 확인, 원하는 섹션으로 바로 이동
- **구체적 방식:** `What’s there`로 우선순위가 높은 섹션들을 제시하고, `More on this page`로 다른 섹션에 접근
- **핵심 근거:** §5–6
- **적용 위치:** 초기 읽기 순서를 강제하지 않고, 탐색 시작점을 안내하는 인터페이스

다만 중요도는 **주어진 쇼핑 과제에 대한 크라우드 순위**로 구성됩니다. 디자이너 의도 추론은 아닙니다. 또한 DASX의 성능 개선은 **KLM-GOMS 기반 분석적 평가**이므로, 실제 사용 실험에서 관측한 시간 단축처럼 인용하면 안 됩니다.

**추천 역할:** 초기 탐색 인터페이스의 직접적인 디자인 참고.

# 6. 특정 기능이 필요할 때 참고할 기술 논문

|논문|가져올 부분|주 모델로 선정하지 않은 이유|
|---|---|---|
|**EyeFormer, UIST’24**|자유 관찰 시선 순서 예측, 시선 좌표를 요소 순서로 대응시키는 방법, 비교 기준|시선 순서와 음성 이해 순서는 다르며, 디자이너 의도를 역추론하지 않음|
|**Morae, UIST’25**|선택지가 드러난 뒤 사용자 선호를 확인하는 방식, 선택지 인지·통제감 평가|주어진 과제 수행 중 선택의 모호성을 다루며, 목표 없는 페이지 탐색이 중심은 아님|
|**Navigal, 첨부 투고 원고**|원문 요소와 연결된 별도 탐색 패널, 안정적 요소 ID, 원문 복귀·검증, 동적 갱신 대응|자연어로 표현한 목표에 맞는 요소 검색이 출발점|
|**CSurf, IUI’07**|이전 링크와 주변 문맥을 이용한 다음 페이지의 관련 영역 우선 제시|이미 관측된 사용자 행동에서 관련성을 추론하며, 디자이너 강조가 중심은 아님|

각각에서 특히 짚어야 할 부분은 다음과 같습니다.

**EyeFormer:** §3, §4.1, §6, §7.4를 참고하면 됩니다. 웹페이지가 포함된 UEyes 데이터를 사용하고, 최대 7초의 자유 관찰을 바탕으로 고정 길이 scanpath를 다룹니다. 따라서 초기 시각적 주의의 비교 기준으로는 유용합니다.

그러나 §6의 응용에서는 **디자이너가 원하는 요소 순서를 입력**하고 그 순서를 유도하도록 레이아웃을 최적화합니다. **완성된 페이지에서 디자이너의 의도된 순서를 찾아내는 실험이 아닙니다.** 또한 개인화에는 대상 관찰자의 시선 표본이 필요하므로 BVI 사용자 개인화에 바로 적용하기 어렵습니다.

**Morae:** §4.1–4.2와 §6이 유용합니다. 탐색 중 관심사가 구체화될 때, 사용자가 선택할 수 있는 내용을 충분히 제시한 다음 선호를 묻는 방식을 참고할 수 있습니다. 사용자 평가에서는 과제 시간이 더 길어졌지만 선호에 맞는 선택과 성공이 증가했습니다. **탐색의 가치를 시간 단축만으로 판단하지 말아야 한다는 근거**로도 중요합니다.

**Navigal:** §3.2–3.3의 tether, 원문 포커스 이동, 요소 ID와 갱신 처리를 참고할 수 있습니다. 수진님 시스템이 추천한 콘텐츠를 **원래 페이지의 실제 요소와 연결**하는 구현에 유용합니다. 단, 첨부본에는 익명 저자·제출 원고·자리표시자 DOI가 표시되어 있으므로, 파일명만 보고 CHI’27 게재 논문으로 표기하면 안 됩니다.

**CSurf:** 사용자가 선택한 링크와 주변 텍스트를 문맥으로 삼아 목적지 페이지의 관련 블록을 먼저 읽습니다. 목표가 일부 드러난 상황에서 참고할 수 있지만, 클릭했다고 해서 목표가 완전히 명확하다고 단정할 수는 없습니다. 또한 첨부 파일명은 `IUI12`지만 **본문의 학회 표기는 IUI’07**입니다.

# 8. 논문들을 실제 구현으로 연결한다면

다음은 선행연구의 결과가 아니라, 위 검토를 바탕으로 한 **구현 제안**입니다.

|단계|구현할 것|주된 참고|
|---|---|---|
|1. 페이지 표현|DOM 요소와 시각적 위치·스타일·콘텐츠 대응|From Cluttered to Clear, Navigal|
|2. 탐색 단위 생성|섹션·카드·제목–본문·이미지–설명 관계 구성|Slide Gestalt, In-Page Navigation Aids|
|3. 강조 추정|요소·섹션의 시각적 중요도와 근거 기록|Learning Visual Importance|
|4. 순서 생성|중요도와 의미적 선후관계를 함께 반영|**새로 설계할 핵심 부분**|
|5. 음성 탐색|시작점 안내, 다음 영역, 상세 읽기, 전체 목록, 원문 복귀|Aural Glancing, Accessible Skimming|
|6. 목표 반영|사용자가 선택한 관심 영역과 제약을 이후 탐색에 반영|Morae, CSurf|

여기서 **4단계를 중요도 내림차순 정렬로 끝내면 안 됩니다.**

예를 들어 할인 배지가 가장 눈에 띄어도, 상품명이 나오기 전에 “30% 할인”부터 읽으면 의미를 이해하기 어렵습니다. 따라서 다음을 구분하는 편이 좋습니다.

- **영역 간 순서:** 어떤 섹션부터 탐색할지
- **영역 내부 순서:** 해당 섹션을 이해하려면 무엇부터 들어야 할지

시각적 강조는 첫 번째의 단서가 될 수 있습니다. 두 번째에서는 제목·대상·설명·조건 같은 의미적 관계가 더 중요할 수 있습니다.

또한 초기 추천에서 밀린 영역도 전체 목록이나 다음 탐색으로 접근할 수 있어야 합니다. 그렇지 않으면 **읽을 대상을 발견하도록 돕는 시스템이 오히려 발견 가능한 범위를 좁힐 수 있습니다.**

# 9. 연구의 타당성을 위해 분리해서 검증할 것

**첫째, ‘무엇을 추론했는가’를 검증해야 합니다.**

디자이너가 의도한 중요도와 관찰자가 지각한 중요도를 각각 수집하는 것이 좋습니다. 둘이 다르면 추론 실패일 수도 있지만, **원래 디자인이 의도를 제대로 전달하지 못한 경우**일 수도 있습니다.

실제 제작자의 의도를 확인하지 못한 데이터에서는 결과를 **시각적으로 전달된 중요도 또는 추론된 전달 우선순위**로 표현하는 편이 정확합니다.

**둘째, ‘왜 효과가 있었는가’를 검증해야 합니다.**

최소한 다음 비교가 필요합니다.

|비교 조건|확인할 것|
|---|---|
|기존 스크린리더 탐색|전체적인 추가 이점|
|구조만 제공|그룹화·제목·개요의 효과|
|구조 + 추론한 강조를 반영한 순서|시각적 강조 정보의 추가 이점|

“강조만으로 정렬한 순서”도 추가하면, 의미적 구조를 함께 고려해야 하는 이유를 분석할 수 있습니다.

**동일한 콘텐츠·요약 길이·이동 기능을 유지하면서 순서를 비교하는 조건**이 특히 중요합니다. 그래야 효과가 요약이나 편리한 버튼 때문인지, 순서 때문인지 구분할 수 있습니다. 생성 지연을 포함한 전체 이용 시간도 별도로 측정해야 합니다.

**셋째, 목표가 불명확한 탐색에 맞는 지표가 필요합니다.**

특정 답을 얼마나 빨리 찾았는지만으로 평가하면 연구 대상이 다시 명확한 목표 탐색으로 바뀝니다.

- 일정 시간 후 페이지의 주제·구조 이해
- 관심 있는 읽을 대상의 발견
- 다음에 읽을 대상을 선택한 이유와 확신
- 발견한 정보의 유용성과 탐색 범위
- 다시 찾기와 위치 파악
- 놓친 정보에 대한 불안, 인지 부담, 통제감

사용자가 더 오래 탐색하더라도, 유용한 대안을 더 많이 발견하고 스스로 선택했다면 가치가 있을 수 있습니다.

모델 페이퍼 두 편을 제시할 때는 **Slide Gestalt의 구조 기반 비시각 탐색**, **Learning Visual Importance의 중요도 추정**을 각각 설명하고, 그 사이에 남는 **“목표가 불명확한 BVI 사용자를 위한 구조·강조 기반 읽기 순서”**를 수진님이 해결할 문제로 놓는 구성이 가장 설득력 있습니다.
