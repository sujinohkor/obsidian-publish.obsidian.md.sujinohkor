*[From Cluttered to Clear: Improving the Web Accessibility Design for Screen Reader Users in E-commerce With Generative AI](https://doi.org/10.1145/3663547.3746353)*
*Yaman Yu*

	이 논문의 핵심은 쇼핑 웹페이지의 HTML을 생성형 AI로 재구성하여, 스크린리더 사용자가 익숙한 탐색 기능으로 중요한 정보에 더 쉽게 접근하도록 만드는 것이야.
	특히 제목 태그를 고치는 것에 더해, 정보를 만나는 순서와 묶음 자체를 바꾼다는 점에서 네 연구와 직접 관련돼. 다만 순서를 정하는 근거는 디자이너 의도의 추론이 아니라, 형성 연구에서 파악한 스크린리더 사용자의 탐색 방식과 정보 요구야.

# Problem — 무엇을 해결하며, 왜 개발되었는가?
**핵심 문제: 쇼핑 웹사이트의 제목·라벨·콘텐츠 순서가 스크린리더 사용자의 탐색 방식과 맞지 않아, 개별 내용에 접근할 수 있어도 페이지 전체를 효율적으로 탐색하기 어렵다는 점.**

**① 스크린리더 탐색에 필요한 정보 구조가 부적절함**

형성 연구에서는 스크린리더로 온라인 쇼핑을 하는 BVI 사용자 6명을 인터뷰하고, 낯선 쇼핑 사이트인 Mercari를 탐색하도록 했어.

참가자들은 제목 이동 키 `H`, 제목 수준별 이동, 아래 화살표를 이용한 순차 읽기 등을 조합했어. 따라서 **어떤 내용을 제목으로 표시하는지, 제목의 수준과 순서가 어떠한지**가 탐색 경험에 직접 영향을 줬어.

문제는 단순히 제목이 없다는 것만이 아니었어.

|문제|구체적인 상황|탐색에 미치는 영향|
|---|---|---|
|**제목 과다**|개별 카테고리·필터마다 제목 태그 부여|불필요한 제목을 여러 번 거쳐야 주요 내용에 도달|
|**필요한 제목 누락**|상품명이 제목으로 표시되지 않음|제목 탐색으로 상품을 찾지 못하고 요소를 하나씩 읽어야 함|
|**불분명한 제목 계층**|상품 설명과 리뷰의 제목 수준이 논리적으로 연결되지 않음|정보 간 관계와 페이지 구조를 파악하기 어려움|
|**부적절한 콘텐츠 순서**|상품명·설명보다 리뷰·공유 기능 등을 먼저 접함|무엇에 대한 정보인지 알기 전에 주변 정보를 처리해야 함|
|**불명확한 버튼 라벨**|기능 설명 없이 “button” 등으로 제시|맥락을 추측하거나 추가 탐색 필요|

따라서 문제는 **접근 가능한 요소의 유무뿐 아니라, 요소를 어떻게 조직하고 노출하는가**에 있어.  
_근거: §4.4.1, §7.5.1–§7.5.3_

**② 낯선 사이트에서는 구조를 새로 학습해야 하는 부담까지 발생**

익숙한 사이트에서는 불편하더라도 주요 정보의 위치나 이동 방법을 기억할 수 있어. 그러나 낯선 사이트에서는 다음을 다시 파악해야 해.

- 제목 탐색을 사용할 수 있는가?
- 상품 정보는 어느 수준의 제목 아래 있는가?
- 카테고리·필터를 얼마나 지나야 검색 결과가 나오는가?
- 어떤 순서로 정보가 제시되는가?

이런 부담은 여러 사이트와 상품을 비교하려는 사용자에게 특히 커져. 형성 연구에서는 상품의 가격·특징을 기억하면서 탭을 오가야 하는 피로도도 보고됐어.

다만 **이 연구가 사이트 간 상품 비교 문제 전체를 해결한 것은 아니야.** 시스템이 직접 다루는 중심은 각 페이지의 구조와 탐색성이야.  
_근거: §1, §4.4_

**③ 개별 요소 개선이나 별도 AI 도우미만으로는 해결되지 않는 문제**

논문은 기존 연구의 상당수가 이미지 설명, 상품 질의응답, 특정 요소의 접근성 개선에 집중했다고 설명해.

이런 기능은 도움이 되지만, 원래 페이지의 제목 구조와 콘텐츠 순서가 그대로라면 **직접 페이지를 탐색할 때의 부담**은 남을 수 있어.

형성 연구 참가자들은 AI를 상품 설명·비교에 활용하기도 했지만, 직접 탐색하면서 통제권을 유지하고 싶다는 선호도 표현했어. 별도 도우미의 신뢰성, 추가 인터페이스, 메시지 인지 문제 등을 우려했기 때문이야.

**개발 이유는 사용자가 새로운 도우미 인터페이스를 배워서 문제를 우회하도록 하기보다, 기존 스크린리더 탐색이 잘 작동하도록 웹페이지 자체를 바꾸기 위해서야.**  
_근거: §2.2–§2.3, §4.4.2–§4.5_

# Core idea — 제안 방법의 핵심 아이디어는 무엇인가?
**핵심 아이디어: 스크린리더 사용자의 탐색 특성을 지침으로 제공하고, LLM이 HTML의 의미 구조와 콘텐츠 배치를 수정하도록 하는 것.**

이 연구는 두 가지 수정 범위를 비교해.

**① 전체 HTML 재생성과 태그 수준 수정의 비교**

|구분|Option 1: Regenerated HTML|Option 2: Reorganized HTML Tags|
|---|---|---|
|기본 접근|HTML을 새로 작성|기존 HTML 태그·속성을 수정|
|콘텐츠 순서|섹션·요소 재배치 가능|원래 순서를 유지하는 제한적 수정|
|시각적 디자인|변경·제거 가능|유지하는 것이 설계 목표|
|구조 변경|새로운 그룹과 설명용 제목 구성 가능|기존 요소의 태그·제목 수준·라벨 중심 수정|
|주요 목적|스크린리더 탐색에 맞춘 폭넓은 재구성|기존 페이지를 보존하면서 접근성 개선|
|주요 절충|콘텐츠 누락·변경 위험 증가|원래 순서에서 발생하는 문제의 개선 범위 제한|

여기서 Option 2의 이름에 _Reorganized_가 들어가지만, **콘텐츠 순서를 폭넓게 재배치하는 버전으로 이해하면 안 돼.** 본문과 부록에서는 기존 레이아웃·내용을 보존하면서 태그와 의미 구조를 수정하는 방식으로 설명해.  
_근거: §5.1–§5.2, Appendix A.2–A.4_

**② 중요한 정보를 적절한 탐색 단위로 구성**

구체적인 변경은 다음과 같아.

- 개별 카테고리를 모두 제목으로 두는 대신, **카테고리 그룹 제목 아래 링크로 배치**
- 상품명을 제목으로 표시하여 **제목 이동으로 상품 접근 가능**
- 구매 관련 버튼들을 **“Purchase Options”라는 제목으로 묶기**
- 상품명·상품 설명을 리뷰나 유사 상품보다 앞에 배치
- 상품명을 제목·링크·리스트 구조 안에 구성하여 **여러 탐색 방식 지원**
- 버튼과 영역에 명확한 라벨·ARIA 정보 제공

즉, **무엇을 제목으로 만들지, 무엇을 묶을지, 무엇을 먼저 읽게 할지를 함께 조정**해.

여기서 추가하는 “요약 제목”은 페이지 내용을 짧은 문단으로 요약하는 것보다, **관련 요소들을 대표하는 그룹 이름을 부여하는 기능**에 가까워.  
_근거: §7.5.4–§7.5.5, Appendix A.5_

**③ 기존 스크린리더 기능을 그대로 활용**

변경 결과는 별도의 대화창이나 독립적인 정보 검색 인터페이스가 아니라, **현재 웹페이지의 HTML에 반영**돼.

사용자는 기존처럼 제목, 링크, 리스트, 버튼을 기준으로 이동해. 시스템의 역할은 그 이동 대상과 순서를 개선하는 것이야.

이 설계는 사용자에게 새로운 명령 체계를 요구하지 않는다는 장점이 있어. 다만 실제 학습 부담이 얼마나 감소하는지를 별도 실험으로 측정하지는 않았어.  
_근거: §5, §7.5.5_

**④ 구현은 GPT-4o 기반 HTML 변환 파이프라인**

Chrome 확장 프로그램이 다음 과정을 수행해.

1. 현재 페이지의 DOM에서 HTML 추출
2. DOM 구조를 고려해 처리 가능한 크기로 분할
3. 스크린리더 탐색 지침과 이전 출력 맥락을 포함해 GPT-4o에 순차 전달
4. 수정된 HTML 또는 태그 결과 결합
5. 원본과의 의미 유사성 검사
6. 검사를 통과한 결과를 현재 페이지에 반영

프롬프트에는 순차 읽기, 제목·링크 단축키, 논리적인 계층과 명확한 라벨 등이 명시돼.

**새로운 모델을 학습하거나, 읽기 순서의 최적화 함수를 정의한 연구는 아니야.** 기존 LLM에 접근성 지침과 페이지 코드를 제공하여 수정 결과를 생성하는 방식이야.  
_근거: §5.2, Appendix A.2–A.4_

**⑤ 콘텐츠 보존 검사 포함**

LLM이 내용을 누락하거나 바꿀 수 있으므로, 원본과 변환본의 다음 정보를 추출해 비교해.

- 스크린리더로 접근 가능한 텍스트
- ARIA 라벨
- 대체 텍스트 등

이를 합친 텍스트의 임베딩 간 코사인 유사도를 계산하고, **90% 이상인 결과를 수용**하는 절차를 설명해. 누락된 링크 등을 프로그램으로 재삽입하거나 재생성을 수행하는 처리도 포함돼.

다만 **전체 의미 유사도가 높다는 사실은 모든 상품명·가격·링크가 정확히 보존됐다는 보장이 아니야.** 이 한계는 결과 해석에서도 중요해.  
_근거: §5.2.1, §6.2, Appendix A.2.4·A.3.4_

# Advantages — 기존 접근보다 어떤 점에서 나은가?
**가장 직접적인 근거는 원래 페이지보다 자동 접근성 검사 결과와 사용자 평가가 개선됐으며, 전체 HTML 재생성이 태그만 수정하는 방식보다 상품 설명 탐색을 더 빠르게 만들었다는 점이야.**

다만 비교 대상은 주로 **원본 사이트와 두 가지 제안 방식**이야. 다른 최신 접근성 시스템이나 전문가가 수동으로 수정한 페이지보다 우수하다는 실험은 아니야.

**① 자동 접근성 검사에서 문제 수 감소**

Amazon·Nordstrom·Mercari의 홈페이지, 검색 결과 페이지, 상품 페이지를 검사했어. 총 9개 페이지 조건에 Lighthouse, SortSite, AChecker를 사용했어.

대표적인 Amazon 상품 페이지 결과는 다음과 같아.

|검사 도구|원본|Option 1: 전체 재생성|Option 2: 태그 수정|
|---|---|---|---|
|Lighthouse|16|**1**|3|
|SortSite|18|**1**|4|
|AChecker|15|**1**|4|

두 방식 모두 검출된 접근성 문제를 줄였고, 전체 재생성이 대체로 더 큰 개선을 보였어.

하지만 이것은 **해당 도구가 검출한 문제 수의 감소**야. 완전한 WCAG 준수나 모든 인터랙션의 접근성을 보장하는 결과는 아니야.  
_근거: §6.1, Table 2_

**② 실제 사용자의 상품 설명 탐색 시간 감소**

사용자 평가의 방법과 인구통계 표에서는 **스크린리더 사용자 15명**이 참여한 것으로 보고돼. 형성 연구 참가자와는 별개야.

각 참가자는 Mercari에서 다음 세 버전을 모두 사용했어.

- 원본
- 전체 HTML 재생성
- 태그 수준 수정

버전 순서는 교차 균형화했으며, 홈페이지 탐색 → 블렌더 검색 결과 탐색 → 선택한 상품 상세 페이지 탐색을 수행했어.

여기서 시간 지표를 정확히 이해해야 해.

**측정한 것은 전체 쇼핑 과제 완료 시간이 아니라, 상품 상세 페이지에서 ‘상품 설명을 찾는 데 걸린 시간’이야.**

홈페이지와 검색 결과에서는 참가자마다 탐색 범위와 발화량이 달라 전체 시간을 비교하기 어렵다고 판단했어. 상품 페이지에서는 모두 상품 설명을 먼저 찾는 행동을 보여 해당 구간을 분석했어.

논문이 보고한 결과는 다음 순서야.

**전체 재생성 < 태그 수정 < 원본**

세 쌍의 비교 모두 통계적으로 유의한 차이를 보고했어. 따라서 **검사 점수뿐 아니라 특정 정보에 도달하는 실제 수행에서도 개선을 확인**한 연구라고 볼 수 있어.  
_근거: §7.1–§7.4.2, Figure 5b_

**③ 사용자 평가는 전체 재생성에 더 유리**

다섯 문항은 다음 내용을 평가했어.

- 전반적인 스크린리더 사용 경험
- 제목의 명확성
- 제목을 통한 계층 이해
- 주요 정보 탐색의 효율성
- 주요 기능 접근의 용이성

논문이 보고한 다중 비교 보정 후 결과는 다음과 같아.

|비교|유의한 차이를 보고한 항목|
|---|---|
|전체 재생성 vs. 원본|**다섯 항목 모두**|
|태그 수정 vs. 원본|**전반적 사용 경험만**|
|전체 재생성 vs. 태그 수정|**전반적 사용 경험만**|

따라서 **전체 재생성이 모든 설문 항목에서 태그 수정보다 통계적으로 우수했다**고 말하면 부정확해.

선호 순위에서는 15명 중 **13명이 전체 재생성을 가장 선호**, 1명은 두 수정 방식을 동등하게 평가, 1명은 태그 수정을 선호했다고 보고돼.  
_근거: §7.4.1, §7.5.2_

**④ 개선의 이유를 사용자 피드백으로 설명**

참가자들이 긍정적으로 평가한 것은 다음과 같아.

- 상품명·설명부터 접하는 논리적인 순서
- 카테고리와 필터로 인한 제목 과부하 감소
- “Purchase Options”와 같은 그룹 제목
- 상품명을 제목으로 찾아갈 수 있는 구조
- 제목·링크·리스트 탐색을 선택할 수 있는 유연성

이는 **태그가 기술적으로 존재하는 것만으로 충분하지 않고, 탐색에 유용하게 배치되어야 한다**는 점을 보여줘.

다만 Option 1은 순서·제목·그룹·라벨 등을 함께 바꿨어. 따라서 **성능 개선을 읽기 순서 변경 하나의 효과로 분리해서 주장할 수는 없어.**  
_근거: §7.5.4–§7.5.5_

**⑤ 콘텐츠 보존에 관한 결과와 한계**

9개 페이지의 전체 재생성 결과에서 의미 유사도는 **91.60~99.36%**였고, 참가자들도 대체로 내용이 비슷하고 위치나 구조가 달라졌다고 평가했어.

하지만 다음은 별개의 문제야.

- 전체 의미가 비슷한가?
- 중요한 세부 정보가 모두 보존됐는가?
- 링크·버튼·폼의 기능이 정상적으로 유지되는가?

연구는 첫 번째를 중심으로 검사했어. 저자들도 작은 누락이나 변경은 여전히 발생할 수 있다고 인정해.  
_근거: §6.2, Table 3, §7.5.6, §8.3_

# Novelty — 무엇이 새로우며, 왜 이전에는 충분히 다뤄지지 않았는가?
**독창성은 생성형 AI를 개별 설명이나 질의응답에 사용하는 데서 확장하여, 페이지 전체의 탐색 구조를 재설계하는 데 적용하고 실제 스크린리더 사용자와 평가했다는 점이야.**

**① ‘웹 접근성에 AI를 처음 사용했다’는 연구는 아님**

논문도 이미 다음 선행연구들이 존재했다고 인정해.

- 이미지 설명 생성
- 상품 관련 질의응답
- 제목·의미 태그 보완
- 표와 문서의 접근성 변환
- LLM을 이용한 접근성 수정

따라서 새로운 점을 **AI 사용 자체**에 두면 안 돼.

이 논문이 강조하는 차이는 **수정 단위를 페이지 전체의 계층·그룹·흐름으로 넓힌 것**이야.  
_근거: §2.2–§2.3_

**② 세 가지 기여의 결합**

|기여|구체적인 내용|
|---|---|
|**사용자 문제 규명**|낯선 쇼핑 사이트에서의 제목 과부하·누락·순서 문제와 직접 탐색 선호 확인|
|**시스템 설계**|기존 스크린리더 사용 방식을 유지하면서 HTML을 재생성하거나 태그 수준에서 수정|
|**비교 평가**|원본·전체 재생성·태그 수정의 차이를 자동 검사와 사용자 평가로 검증|

연구의 중심은 **사용자 요구를 반영한 페이지 재구성 방식과 그 효과**야. 새로운 LLM 구조나 독립적인 순서 추론 알고리즘이 핵심 기여인 논문은 아니야.

**③ “왜 이전에는 하지 않았는가?”에 대한 근거 있는 해석**

논문이 이전 연구자들의 선택 이유를 직접 조사한 것은 아니야. 본문에서 확인되는 장애요인을 바탕으로 다음과 같이 해석할 수 있어.

**첫째, 국소적인 오류 수정과 전체 구조 설계는 다른 문제임.**  
라벨이 비어 있는지는 비교적 명확하지만, 어떤 항목을 제목으로 만들고 어느 그룹에 넣고 무엇을 먼저 제시할지는 사용자 행동과 콘텐츠 맥락을 함께 고려해야 해.

**둘째, HTML을 수정할 수 있어도 사용자의 탐색에 적합한지는 별도 문제임.**  
접근성 규칙을 만족하는 태그가 있더라도 제목이 너무 많거나 순서가 부적절하면 불편할 수 있어. 형성 연구와 사용자 평가가 필요한 이유야.

**셋째, 폭넓은 재구성에는 보존 위험이 따름.**  
원본을 자유롭게 바꿀수록 정보 누락, 링크 손실, 기능 변경 가능성도 커져. 논문이 두 수정 범위와 유사성 검사를 도입한 배경이기도 해.

**넷째, LLM을 통한 맥락 기반 코드 수정이 이러한 접근을 구현할 수 있는 수단을 제공함.**  
이 연구는 기존 LLM을 활용하여 섹션의 역할과 관련 내용을 바탕으로 HTML을 재작성했어. 다만 규칙 기반 방법보다 반드시 우수하다는 직접 비교는 수행하지 않았어.

**④ 실서비스 수준으로 해결되지 않은 문제**

- **처리 지연:** 부록에 페이지당 **1~5분**의 처리 시간 보고
- **콘텐츠 손실:** 의미 유사성 검사로 모든 세부 정보 누락을 검출하기 어려움
- **동적 웹페이지:** 비동기 로딩, 무한 스크롤, JavaScript 중심 DOM 변경에 대한 일반화 미해결
- **평가 범위:** 사용자 평가는 Mercari 한 사이트와 세 페이지 유형에 한정
- **과제 범위:** 결제 완료까지의 전체 쇼핑 과정 검증 없음
- **기기 범위:** 데스크톱 중심 평가이며 모바일·태블릿 검증 부족
- **개인화:** 사용자별 탐색 목적이나 선호에 맞춰 순서를 조정하는 효과 미검증

따라서 논문에서 “동적으로 재구성한다”고 표현하더라도, **모든 사이트를 즉시 안정적으로 변환하는 완성된 시스템으로 이해하면 안 돼.**

저자들도 확장 프로그램을 개념 검증용 구현으로 설명하며, 장기적으로는 개발자의 접근성 설계·수정 과정에 활용하는 방향을 강조해.  
_근거: §8.1–§8.3, Appendix A.1_

# 내 연구와의 관계
이 논문은 **웹페이지의 읽기 순서 변경과 직접 겹치는 선행연구**야.

|관점|이 논문|네 연구 방향|
|---|---|---|
|문제|페이지 구조와 스크린리더 탐색 방식의 불일치|목표가 불명확한 BVI 사용자의 웹 탐색|
|순서 구성 근거|사용자 인터뷰에서 확인한 정보 요구와 탐색 방식|시각적 강조·구조에서 추론한 디자이너 의도|
|주요 개입|HTML 순서·제목·그룹·라벨을 함께 수정|추론한 의도를 단서로 읽기 순서 구성|
|사용자 의도|자유로운 초기 탐색과 블렌더 탐색 과제 포함|의도가 불명확하거나 부분적으로 정해진 상태에 명시적 초점|
|검증|상품 설명 탐색 시간, 사용성, 구조 이해 자기보고|해당 의도 상태에서의 탐색 효율과 이해 효과 검증 필요|

여기서 두 가지를 분명히 해야 해.

**첫째, 이 논문에도 자유 탐색이 포함돼.** 따라서 기존 연구는 모두 목표가 완전히 정해진 상황만 다뤘다고 주장할 수 없어. 다만 **의도의 명확성을 분류하거나 조작하여, 상태별 효과를 비교하지는 않았어.**

**둘째, “읽기 순서를 바꾸면 탐색이 좋아진다”만으로는 네 연구의 차별성이 충분하지 않아.** 이 논문은 이미 순서와 구조를 바꾸는 접근을 보여줬어. 네가 제시한 연구 방향에서 추가로 답해야 하는 질문은 **왜 디자이너 의도를 순서 구성의 단서로 선택하는지, 그 단서를 어떻게 추론하는지, 그리고 그것이 목표가 불명확한 사용자에게 어떤 추가적인 이점을 주는지**야.
