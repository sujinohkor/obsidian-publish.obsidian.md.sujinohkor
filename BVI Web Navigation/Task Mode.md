*[Task Mode: Dynamic Filtering for Task-Specific Web Navigation using LLMs](https://doi.org/10.1145/3663547.3746401)*
*Ananya Gubbi Mohanbabu*

	Task Mode는 사용자가 입력한 목표를 기준으로 웹페이지 요소의 관련성을 평가하고, 관련성이 낮은 요소를 숨기거나 시각적으로 약화하여 탐색 부담을 줄이는 시스템이야.

# Problem — 무엇을 해결하며, 왜 개발되었는가?
**핵심 문제: 웹페이지에는 다양한 목적을 위한 정보가 함께 존재하지만, 사용자는 현재 목표와 무관한 내용까지 탐색해야 한다는 점. 이 부담이 스크린리더 사용자에게 특히 크게 작용함.**

**① 접근할 수 있는 페이지라도 효율적으로 탐색하기 어려움**

웹사이트는 여러 사용자의 목적을 동시에 지원하도록 구성돼. 예를 들어 쇼핑 사이트에는 상품 목록뿐 아니라 카테고리, 추천 상품, 할인 배너, 회사 소개 등 다양한 요소가 있어.

그러나 사용자의 현재 목표가 “500달러 이하의 크롬북이 아닌 노트북 구매”라면, 이 중 상당수는 당장 필요하지 않아.

시각을 사용하는 사용자인 **VU(Vision User)**는 화면을 훑으며 관련 없는 부분을 건너뛸 수 있어. 반면 **SRU(Screen Reader User)**는 관련 없는 요소를 음성으로 확인하거나 여러 번 이동해야 할 수 있어.

스크린리더에도 제목·랜드마크 이동 기능은 있지만, 다음과 같은 한계가 있어.

- 제목이나 랜드마크가 적절히 제공되지 않는 페이지 존재
- 구조가 적절해도 각 섹션이 현재 목표와 관련 있는지는 사용자가 판단해야 함
- 관련 없는 제목·링크·상품이 많으면 반복적인 이동 필요

따라서 이 연구의 문제는 **접근성 오류의 존재뿐 아니라, 목표와 무관한 정보로 인한 사용성 격차**야.  
_근거: §1, §2.1_

**② 기존 개선 방식은 ‘현재 목표와의 관련성’을 충분히 반영하지 못함**

|기존 접근|제공하는 도움|남는 문제|
|---|---|---|
|제목·라벨·ARIA 보완|요소와 구조에 접근하기 쉽게 함|현재 목표와 무관한 내용도 계속 탐색해야 함|
|페이지 재구성·요약|내용을 정돈하거나 압축|특정 사용자의 현재 목표와 맞는 정보만 선별하는 것과는 차이|
|광고 차단·방해 요소 제거|정해진 유형의 요소 억제|같은 유형의 요소도 목표에 따라 필요성이 달라짐|
|사용자가 직접 요소 숨기기|개인별 화면 조정|사용자가 먼저 요소를 찾고 선택해야 함|
|웹 에이전트|클릭·입력 등을 대신 수행|오류 복구, 통제권 전환, 수행 과정 파악의 부담 발생 가능|

예를 들어 “추천 상품”은 항상 불필요한 것이 아니야. 원하는 상품과 일치하는 추천은 유용할 수 있어.

**필요한 것은 요소 유형만을 기준으로 제거하는 규칙보다, ‘이 요소가 현재 목표 달성에 도움이 되는가’를 판단하는 기능**이라는 것이 저자들의 논리야.  
_근거: §1, §2.1–§2.3_

**③ 사용자 통제권을 유지하면서 불필요한 탐색을 줄일 필요**

웹 탐색에는 단순히 정해진 버튼을 누르는 것뿐 아니라 비교, 판단, 추가 정보 확인, 목표 수정이 포함돼.

저자들은 사용자가 이러한 판단을 계속 수행하면서도, 관련 없는 정보를 지나치는 부담은 줄일 수 있다고 봐.

따라서 개발 목적은 **사용자의 탐색을 목표에 맞게 지원하고, 기존 웹·스크린리더 사용 방식을 유지하면서 불필요한 정보 처리량을 줄이는 것**이야.  
_근거: §2.3, §3.1_

# Core idea — 제안 방법의 핵심 아이디어는 무엇인가?
**핵심 아이디어: 사용자가 자연어로 표현한 목표를 구조화하고, 웹 요소의 의미와 주변 맥락을 고려해 관련성 점수를 부여한 뒤, 그 점수에 따라 표시 방식을 조정하는 것.**

**① 사용자 목표를 다섯 요소로 분해**

사용자가 목표를 입력하면 GPT-4o가 다음과 같이 구조화해.

|구성 요소|의미|“500달러 이하 노트북 구매”에 적용한 설명용 예시|
|---|---|---|
|**Entity**|찾는 대상|노트북|
|**Constraints**|조건·선호|가격 500달러 이하|
|**Actions**|목표 달성에 필요한 행동|검색, 필터 적용, 비교, 장바구니 추가|
|**Defaults**|해당 과제에서 통상 필요한 정보|상품명, 가격, 이미지|
|**Fallbacks**|기본 경로가 없을 때 사용할 대안|검색창, 고객 지원|

표의 예시는 구조를 설명하기 위한 것이고, 실제 실행 결과를 재현한 것은 아니야.

이 분해의 목적은 **목표에 직접 등장한 단어 외에도, 그 목표를 수행하는 데 필요한 정보와 조작 요소를 찾아내는 것**이야.

예를 들어 “노트북”이라는 단어가 없어도 검색창이나 장바구니 버튼은 과제 수행에 필요할 수 있어.  
_근거: §4.2.2, Appendix A.1_

**② 요소를 독립적으로 보지 않고 주변 관계까지 고려**

시스템은 DOM에서 텍스트, 제목, 링크, 버튼, 이미지, SVG 등을 추출하고 요소 ID, 태그, 부모·자식 관계 등을 기록해.

그다음 텍스트 요소마다 **0~100의 과제 관련성 점수**를 부여해.

중요한 점은 같은 텍스트도 맥락에 따라 점수가 달라져야 한다는 것이야.

- 노트북 상품 카드 안의 **“$499”**: 예산 조건 판단에 유용
- 무관한 상품 카드 안의 **“$499”**: 숫자가 같아도 관련성은 낮음
- 조건에 맞는 상품의 **“Add to cart”**: 목표 수행에 유용
- 무관한 상품의 **“Add to cart”**: 같은 버튼 문구라도 필요성이 낮음

부록 프롬프트에서도 상품 카드·리스트·섹션을 의미 단위로 해석하고, 관련 상품에 연결된 가격과 버튼을 함께 평가하도록 지시해.

따라서 **단순 키워드 일치가 아니라, 과제 조건과 요소 간 관계를 반영한 관련성 평가**가 핵심이야.  
_근거: §4.2.1–§4.2.2, Appendix A.2_

**③ 텍스트 외의 이미지와 아이콘도 평가**

- **이미지:** GPT-4o를 통한 대체 텍스트 관련성 평가와 CLIP을 통한 이미지–과제 유사도를 결합
- **SVG 아이콘:** SVG 경로를 GPT-4o에 제공해 검색·장바구니 등의 의미를 추정한 뒤 과제 관련성 평가
- **대체 텍스트가 없는 이미지:** 이미지 자체와 과제의 유사도 사용

클릭 가능한 요소만 다루지 않고, 제목·본문·이미지처럼 **판단에 필요한 비상호작용 요소까지 포함**한다는 점이 중요해.

다만 각 처리 방식의 정확도를 별도로 충분히 검증한 결과나, 구성 요소별 기여를 분리한 실험은 제시되지 않아.  
_근거: §4.2.2_

**④ 접근 방식에 따라 세 가지 표시 모드 제공**

|모드|작동 방식|주된 효과|
|---|---|---|
|**Color Gradients**|모든 요소를 유지하고 관련성에 따라 색상 표시|시각적으로 관련 영역 식별|
|**Varying Opacity**|관련성이 낮은 요소를 흐리게 표시|전체 맥락을 남기면서 시각적 방해 감소|
|**Only Task-Specific Information**|임계값보다 낮은 요소를 숨기고 상호작용 차단|스크린리더가 무관한 내용을 건너뛰도록 지원|

완전 필터링 모드에서는 낮은 점수의 요소를 시각적으로 숨기는 데 더해, `aria-hidden` 등을 적용하여 보조기술에서도 제외해.

**화면에서 흐리게 보이는 것만으로는 스크린리더의 읽기 부담이 줄지 않기 때문에**, 시각적 약화와 접근성 트리에서의 제외를 구분한 설계야.  
_근거: §4.1, §4.2.3_

**⑤ 필요한 상위 구조를 보존**

관련 있는 요소가 남더라도 그 요소를 포함하는 상위 컨테이너가 사라지면 내용이 끊어질 수 있어.

이를 막기 위해 필터링 모드에서는 **관련 요소의 조상 노드를 DOM 상위 방향으로 유지**해. 투명도 모드에서도 자식의 높은 점수를 부모에 반영해 관련 내용이 함께 흐려지는 문제를 줄여.

다만 **조상 컨테이너를 유지하는 것만으로 의미적 맥락이 완전히 보존되는 것은 아니야.** 실제 평가에서 본문은 남았지만 연결된 제목이 사라지는 사례가 보고됐어. 제목은 본문의 조상이 아니라 같은 컨테이너의 형제 요소일 수도 있기 때문이야.  
_근거: §4.2.3, §5.2.1, Figure 4_

**⑥ 사용자가 목표와 필터링 강도를 조절**

사용자는 탐색 중 다음을 변경할 수 있어.

- 과제 설명
- 관련성 임계값
- 표시 모드

과제 맥락은 페이지 이동 중에도 유지하도록 설계됐어. 임계값을 낮추면 더 넓은 관련 정보를, 높이면 더 제한된 정보를 볼 수 있어.

여기서 **임계값 75%는 상위 25%의 요소만 남긴다는 뜻이 아니야.** 모델이 부여한 관련성 점수에 적용하는 기준이지, 남길 콘텐츠의 비율을 직접 지정하는 값은 아니야.

또한 목표 변화는 사용자가 설명을 수정하여 반영하는 방식이야. **사용자의 행동을 관찰해 목표 변화를 자동으로 추론하는 시스템으로 설명하면 부정확해.**  
_근거: §3.1, §4.1–§4.2.3_

# Advantages — 기존 접근보다 어떤 점에서 나은가?
**가장 강한 근거는 스크린리더 사용자에게서 과제 수행 시간이 약 52% 감소했고, 정신적 부담과 정보 찾기의 어려움도 줄었다는 점이야.**

다만 **필터링 정확도, 실제 대기 시간, 사용자 집단별 효과를 구분해서 해석해야 해.**

**① 스크린리더 사용자의 과제 수행 시간 감소**

사용자 연구에는 총 12명이 참여했어.

- 스크린리더 사용자 6명: 모두 전맹
- 시각을 사용하는 사용자 6명

통제 실험은 Wikipedia, CNN, H-E-B에서 정보 찾기, 탐색, 구매 관련 판단을 다뤘어.

|사용자 집단|기존 탐색|Task Mode|통계적 결과|
|---|---|---|---|
|**SRU**|211.25초|**102.21초**|유의한 감소, p=.031|
|**VU**|106.87초|**84.43초**|유의한 차이 없음, p=.563|

SRU의 평균 시간은 약 **51.6% 감소**했어. 두 집단 평균의 비율도 약 **2.0배에서 1.2배**로 줄었어.

다만 이 비율은 해당 표본의 평균을 비교한 결과야. **모든 사용자에게 접근 방식에 따른 격차가 같은 정도로 줄어든다고 일반화할 수는 없어.**  
_근거: §5.1–§5.2, Tables 3–4_

**② 이 시간 비교는 실시간 처리 대기를 포함한 성능으로 보면 안 됨**

이 논문의 중요한 평가 조건이야.

- 통제 실험에서는 9개 웹사이트–과제 조합에 대해 **미리 처리한 동일한 결과**를 참가자에게 제공
- 자유 과제에서도 SRU는 사이트와 과제를 미리 제출하고, 연구자가 사전 처리한 결과를 사용
- VU의 자유 과제는 연구자 컴퓨터에서 실시간 실행

따라서 약 52%의 감소는 **준비된 Task Mode 결과를 이용한 탐색 효율**에 대한 근거야. 새 페이지마다 AI가 처리하는 시간을 포함한 전체 경험에서 같은 감소율이 나온다는 뜻은 아니야.

별도의 기술 평가에서 보고한 처리 지연은 페이지당 평균 **10.68초**, 비용은 실험 당시 기준 평균 **$0.102**였어.  
_근거: §4.4, §5.1.2_

**③ SRU의 정신적 부담과 정보 찾기 용이성 개선**

5점 척도에서 다음 차이가 보고됐어.

|지표|기존 탐색|Task Mode|해석|
|---|---|---|---|
|정신적 부담|3.72|**2.28**|유의한 감소|
|신체적 부담|2.11|**1.44**|유의한 감소|
|정보 찾기 용이성|2.44|**4.11**|유의한 개선|
|노력|3.28|2.89|유의한 차이 없음|
|좌절감|2.78|2.28|유의한 차이 없음|
|전반적 만족도|2.39|3.33|유의한 차이 없음, p=.058|

따라서 **“모든 부담과 만족도 지표가 유의하게 개선됐다”는 설명은 부정확해.**

참가자 발언은 대체로 긍정적이었지만, 통계적으로 확인된 항목과 정성적 선호를 구분해야 해. 여러 지표를 검정한 결과에 대한 다중 비교 보정도 본문에서 명시적으로 설명되지 않아, 작은 표본의 초기 근거로 보는 것이 적절해.  
_근거: §5.2.1, Table 4_

**④ 원문을 직접 확인하면서 사용자가 결정 가능**

Task Mode는 관련 내용을 원래 페이지에서 보여줘. 사용자가 직접 읽고, 클릭하고, 비교할 수 있어.

참가자들은 다음을 장점으로 언급했어.

- 새로운 조작 방식을 많이 배우지 않아도 됨
- 원래 사이트의 구조를 활용할 수 있음
- 정보의 출처와 주변 맥락을 직접 확인할 수 있음
- 원하는 정보 범위에 맞춰 필터링을 조정할 수 있음

전체 12명 중 **11명**이 향후 사용 의향을 보였어.

다만 **원문을 그대로 보여준다고 해서 판단 오류가 없어지는 것은 아니야.** Task Mode의 주요 오류는 새로운 문장을 잘못 생성하는 것보다, 필요한 원문을 잘못 숨기는 형태로 나타날 수 있어.  
_근거: §5.2.1, §5.2.3, §6.2.1_

**⑤ 정확한 검색어가 없어도 의미적으로 관련된 정보 탐색 가능**

참가자들은 검색어와 페이지 표현이 일치하지 않는 경우, 사이트가 제공하지 않는 세부 조건으로 상품을 보고 싶은 경우에도 유용하다고 평가했어.

예를 들어 사이트에 특정 조건의 필터가 없어도, 그 조건을 과제 설명에 넣어 관련 내용을 강조하도록 할 수 있어.

이는 **사용자가 표현한 목표를 페이지의 기존 검색·필터 구조보다 유연하게 적용할 수 있다는 가능성**을 보여줘.

그러나 조건 충족 여부를 보장하는 엄격한 검색 엔진은 아니야. 부록 프롬프트에는 일부 조건을 충족하는 카드도 관련 있다고 평가하도록 하는 지침이 있어. 따라서 **관련성 점수가 높다는 것과 모든 조건을 충족했다는 것은 다름**을 기억해야 해.  
_근거: §5.2.1, §5.2.3, Appendix A.2_

**⑥ 에이전트보다 낫다는 주장은 범위 제한**

웹 에이전트 비교는 **VU에게만** 실시했어. 사용한 비교 시스템은 CowPilot이야.

Task Mode는 에이전트보다 시간적 부담과 전반적 만족도에서 유의한 이점을 보였지만, **과제 수행 시간 차이는 유의하지 않았어.**

SRU에게서는 에이전트 조건을 제외했으므로, **Task Mode가 SRU용 웹 에이전트보다 우수하다고 직접 검증한 연구는 아니야.**  
_근거: §5.1, §5.1.3, Table 3_

# Novelty — 무엇이 새로우며, 왜 이전에는 충분히 다뤄지지 않았는가?
**독창성은 사용자 목표에 따라 웹 요소를 자동으로 선별하고, 원래 구조와 사용자 통제권을 유지하면서 시각·비시각 접근에 맞는 방식으로 제공한 데 있어.**

**① ‘관련 없는 내용을 줄이면 좋다’는 아이디어 자체는 기존에 존재**

논문은 특정 과제에 맞춰 모의 웹페이지에서 불필요한 내용을 수동 제거했을 때, SRU의 수행 시간이 개선된 선행연구를 명시적으로 인용해.

따라서 **과제 관련 정보만 제공하는 효과를 처음 발견했다**고 설명하면 안 돼.

저자들이 제시하는 확장은 다음과 같아.

- 수동으로 편집한 모의 페이지에서 **복잡한 실제 웹사이트로 확장**
- 연구자가 미리 정한 선별에서 **LLM 기반 자동 관련성 평가로 확장**
- 고정된 과제 표현에서 **수정 가능한 자연어 목표로 확장**
- 단일 표현 방식에서 **시각·비시각 사용자에게 맞는 여러 표시 방식으로 확장**

_근거: §2.1, §6_

**② 기존 접근과 다른 핵심 조합**

|비교 관점|Task Mode의 차별점|
|---|---|
|일반적인 접근성 수정|현재 과제와의 관련성을 기준으로 노출 요소 조정|
|광고·방해 요소 차단|요소 유형이 아니라 목표에 따른 의미적 관련성 평가|
|키워드 검색|조건, 관련 행동, 주변 요소의 관계까지 고려|
|페이지 재작성|기존 콘텐츠와 구조를 활용하면서 선택적으로 억제|
|자동 수행 에이전트|사용자가 직접 판단·행동하도록 탐색 환경 조정|
|시각 사용자 중심 도구|처음부터 SRU와 VU의 접근 방식을 함께 고려|

새로운 LLM 아키텍처나 학습 방법을 제안한 논문은 아니야. **과제 구조화, 요소 관련성 평가, DOM 기반 표시 제어, 사용자 조절 기능을 연결한 인터랙션 시스템**이 기여의 중심이야.

**③ “왜 이전에는 하지 않았는가?”에 대한 근거 있는 해석**

이 질문에 대한 역사적 원인을 논문이 직접 입증한 것은 아니야. 다만 다음 기술적·설계적 어려움을 확인할 수 있어.

**첫째, 관련성은 고정된 속성이 아님.**  
같은 메뉴·상품·문단도 사용자 목표에 따라 필요성이 바뀌어. 유형별 차단 규칙만으로는 이런 변화를 다루기 어려워.

**둘째, 개별 요소만 보면 의미가 불완전함.**  
가격, 배송 조건, 장바구니 버튼은 어느 상품에 연결되어 있는지 알아야 해. 실제 페이지의 반복되는 카드와 DOM 관계를 고려해야 하는 이유야.

**셋째, 내용을 숨기는 행위는 정보 누락 위험을 동반함.**  
불필요한 내용을 덜 제거하면 효과가 작아지고, 너무 많이 제거하면 필요한 맥락과 기능이 사라져. 필터링 강도와 맥락 보존의 절충이 필요해.

**넷째, 시각·비시각 사용자에게 필요한 표현 방식이 다름.**  
시각 사용자는 흐린 내용도 확인할 수 있지만, SRU에게는 실제 탐색 대상에서 제외해야 이동 부담이 줄어. 같은 관련성 판단을 접근 방식에 맞게 표현해야 해.

**다섯째, 실제 웹페이지의 규모와 동적 변화.**  
수천 개 요소의 관련성을 평가하면서 응답 속도를 유지하고, 스크롤이나 프레임워크에 의해 바뀌는 콘텐츠까지 처리해야 해.

이 연구는 LLM을 이용해 이 문제들을 구현 가능한 수준으로 연결했지만, 완전히 해결하지는 못했어.  
_근거: §4.2–§4.4, §6.2.1_

**④ 남는 핵심 한계**

- **목표 오해·점수 불일치:** LLM이 필요한 요소를 낮게 평가하거나 무관한 요소를 높게 평가할 수 있음
- **맥락 단절:** 제목 없이 본문 일부만 남거나 문단 안의 링크가 사라지는 사례 존재
- **검증 부담:** 사용자가 임계값을 낮추거나 원본과 비교해 누락 여부를 확인해야 할 수 있음
- **동적 콘텐츠:** 가상화 무한 스크롤처럼 DOM을 재사용하는 방식에서 갱신된 내용 누락
- **접근 불가능한 표현:** Canvas·WebGL 내부 콘텐츠를 의미적으로 분석하지 못함
- **작은 표본:** SRU 6명·VU 6명이며, SRU는 모두 전맹이고 숙련도가 대체로 높음
- **구성 요소별 효과 미분리:** 과제 분해, 이미지 처리, 맥락 지침 등이 각각 얼마나 기여했는지 불명확

20개 사이트 중 19개에서 요소를 파싱하고 표시했다고 보고했지만, **이것은 관련성 판정 정확도 95%라는 뜻이 아니야.** 정답 관련성 주석에 대한 precision·recall 평가와 구분해야 해.  
_근거: §4.4, §5.1.1, §5.2.1, §6.2.1_

# 내 연구에서 특히 중요하게 읽어야 할 부분
Task Mode를 **“목표가 100% 명확할 때만 작동하는 연구”로 분류하면 부정확해.**

논문은 명시적으로 **명확한 목표와 모호한 목표 모두에서의 유용성**을 논의해. 정확한 검색어를 모르거나, 탐색 중 조건을 수정하는 상황도 포함돼.

하지만 다음 구분은 가능해.

|사용자 상태|Task Mode와의 관계|
|---|---|
|구체적인 대상·조건이 정해져 있음|직접적인 지원 대상|
|관심 주제나 대략적인 필요는 있지만 세부 조건이 미정|자연어 목표를 입력하여 활용 가능하며 정성적 근거 존재|
|탐색 중 목표가 바뀜|사용자가 목표 설명을 수정하도록 지원|
|어떤 주제를 볼지조차 정하지 못해 목표를 표현하기 어려움|별도의 지원 방식과 효과를 검증하지 않음|

즉, **목표의 완전한 확정 여부보다, 필터링의 기준이 될 목표를 사용자가 표현할 수 있는지가 중요한 전제**야.

또한 Task Mode가 제공하는 관련성 점수는 **읽기 순서 자체가 아니야.** 원래 순서 안에서 요소를 숨기거나 강조하므로, 관련 내용을 어떤 논리로 앞뒤에 배치할지에 대한 연구와는 차이가 있어.

|관점|Task Mode|네가 앞서 제시한 연구 방향|
|---|---|---|
|출발점|사용자가 입력한 목표|불명확하거나 부분적으로 정의된 목표|
|핵심 단서|목표와 콘텐츠의 의미적 관련성|시각적 강조·구조에서 추론한 디자이너 의도|
|주요 개입|요소 표시·억제|읽기 순서 구성|
|사용자 조절|목표 수정·임계값·표시 모드 변경|구체적인 상호작용 설계 필요|
|핵심 검증|목표 기반 필터링의 탐색 효율|추론한 의도가 탐색 단서로 유용한 조건과 효과|

따라서 차별성을 **“기존 연구는 명확한 목표만 다루지만 우리는 불명확한 목표를 다룬다”**로 잡기에는 부족해. Task Mode도 부분적으로 정의된 목표를 다루기 때문이야.

네 연구에서는 **사용자가 제공할 수 있는 목표 정보가 제한적일 때, 디자이너 의도에서 얻은 단서가 무엇을 추가로 제공하는지**, 그리고 **그 단서를 읽기 순서에 반영했을 때 목표 기반 필터링과 어떤 차이가 생기는지**를 설명하는 것이 중요해.
