중요도(Importance)와 디자이너의 의도(Designer Intent)는 다릅니다.
- 중요도: 어떤 정보가 더 중요하거나 주목할 만한가?
- 디자이너 의도: 디자이너가 해당 정보를 통해 무엇을 전달하거나, 사용자가 무엇을 이해하고 행동하도록 유도하려는가?

따라서 원하시는 것은 중요도가 비슷한 DOM 요소를 묶는 것이 아니라, 동일한 정보 전달 목적을 수행하는 DOM 요소를 하나의 그룹으로 묶는 것입니다.

# 1. 제가 제안하는 그룹화 기준
핵심 기준은 **Communicative Purpose(정보 전달 목적)**입니다.

|판단 기준|구체적인 질문|활용할 단서|
|---|---|---|
|① 전달 목적|이 요소들은 사용자에게 무엇을 전달하려는가?|제목, 문구, 이미지, CTA|
|② 의미적 관계|요소들이 하나의 메시지를 구성하는가?|설명·보충·비교·근거 관계|
|③ 기능적 관계|요소들이 동일한 사용자 행동을 지원하는가?|가격·옵션·구매 버튼, 입력 필드·레이블|
|④ 시각적·구조적 관계|디자이너가 이 요소들을 하나의 단위로 표현했는가?|공통 컨테이너, 근접성, 정렬, 여백, 제목 계층|

중요한 것은 네 기준을 모두 만족해야 그룹화한다는 뜻이 아니라, 여러 단서를 종합하여 공통된 정보 전달 목적을 추론한다는 것입니다.

# 2. 실제 상품 페이지에 적용하면
다음과 같은 DOM 요소들이 있다고 가정하겠습니다.

**Group A. 상품을 소개하려는 의도**
- 상품명 + 대표 이미지 + 특징 + 상품 설명
- 추론된 의도: 사용자가 상품이 무엇인지 이해하도록 한다.

**Group B. 구매를 유도하려는 의도**
- 가격 + 색상·사이즈 옵션 + 재고 상태 + 구매 버튼
- 추론된 의도: 사용자가 구매 조건을 확인하고 구매하도록 한다.

**Group C. 상품의 신뢰성을 전달하려는 의도**
- 고객 평점 + 리뷰 + 구매 후기
- 추론된 의도: 다른 사용자의 경험을 통해 구매 판단을 뒷받침한다.

**Group D. 추가 상품을 홍보하려는 의도**
- 추천 상품 + 관련 상품 + 프로모션
- 추론된 의도: 사용자의 관심을 다른 상품으로 확장한다.

이렇게 그룹화하면 각 그룹의 시각적 중요도가 동일할 필요가 없습니다.

또한 상품명과 가격은 서로 의미적으로 관련되어 있지만, 디자이너가 수행하려는 정보 전달 기능이 다르다면 별개의 그룹으로 분리할 수 있습니다.

위 분류는 검증된 정답이 아닌 초기 설계 가설입니다.

# 3. 논문에서 얻을 수 있는 근거
## Slide Gestalt (CHI 2023)
저작자가 제목, 레이아웃, 반복되는 시각 패턴 등을 활용해 정보 구조를 표현한다는 점을 보여줍니다. 따라서 시각적 구성에서 저작자의 구조화 의도를 추론하는 접근을 뒷받침합니다. 다만 연구 대상은 웹페이지가 아닌 슬라이드입니다.
## Task Mode (ASSETS 2025)
개별 DOM 요소만으로 의미를 판단하지 않고, 상위 컨테이너와 주변 요소의 맥락을 함께 고려합니다. 이를 통해 가격과 상품명처럼 서로 다른 종류의 요소가 어떤 관계를 갖는지 해석할 수 있습니다.
## In-Page Navigation Aids (TACCESS 2024)
문장 간 의미적 유사성과 주제 경계를 이용하여 콘텐츠를 분할합니다. 다만 이것은 주제 기반 그룹화의 근거이지, 디자이너의 정보 전달 의도를 직접 추론하는 방법은 아닙니다.

즉, 첨부 논문들은 의도 추론에 사용할 개별 단서를 뒷받침하지만, 이 단서들을 결합해 디자이너 의도 기반 DOM 그룹화를 수행하는 완성된 기준을 직접 제공하지는 않습니다. 그 기준은 연구에서 설계하고 검증해야 합니다.

# 4. 실제 LLM 그룹화 방법
저라면 LLM에 단순히 Group related elements라고 요청하지 않겠습니다.

다음 세 질문을 순서대로 판단하도록 설계하겠습니다.
1. 이 웹페이지가 전반적으로 수행하려는 정보 전달 목적은 무엇인가? (예: 상품 소개 및 판매)
2. 각 DOM 요소 또는 요소 집합은 어떤 세부 전달 목적을 수행하는가? (예: 소개, 설명, 설득, 행동 유도)
3. 동일한 전달 목적을 수행하면서 의미적·기능적·시각적 관계가 확인되는 요소들은 무엇인가?

그리고 그룹별로 다음 정보를 출력하도록 합니다.

```
{
  "group_id": "B",
  "group_name": "Price and Purchase Options",
  "inferred_intent": "Encourage product purchase",
  "dom_elements": [
    "price",
    "color_selector",
    "size_selector",
    "purchase_button"
  ],
  "evidence": [
    "Shared purchase-related function",
    "Common visual container",
    "Related controls and labels"
  ]
}
```

여기서 특히 중요한 필드는 **`inferred_intent`와 `evidence`**입니다.

단순히 요소들을 묶는 것에서 끝나지 않고, 왜 디자이너가 이 요소들을 하나의 정보 전달 단위로 구성했다고 추론했는지 근거를 남기기 때문입니다.

물론 DOM의 컨테이너나 시각적 근접성만으로 실제 디자이너의 의도를 확정할 수는 없습니다. 그래서 `inferred`라는 표현을 유지해야 합니다.

# 결론

현재 연구에서 그룹화의 중심 질문은 이것이어야 합니다.

"Which DOM elements serve the same inferred communicative purpose?"
즉, 어떤 DOM 요소들이 동일한 것으로 추론되는 정보 전달 목적을 수행하는가?

이것을 기본 그룹화 원칙으로 설정하고, 의미적 관계·기능적 관계·시각적 구조를 그 판단의 근거로 사용하는 방식을 권장합니다.

그리고 그룹 A, B, C를 만든 후 어떤 순서로 탐색할지는 별도의 문제로 남겨두어야 합니다. 그룹의 정보 전달 목적과 그룹의 탐색 우선순위는 같지 않기 때문입니다.
